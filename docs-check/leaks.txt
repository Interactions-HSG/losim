# What the manual and the simulator's own source may not contain, one rule per
# line:
#
#     <extended regex>:::<what it would give away>
#
# Matched case-insensitively against every text file under docs/ and losim/src,
# except this directory. A hit fails the build. Nothing here is about style —
# every rule names a thing a student is supposed to arrive at themselves, and a
# page that contains it has handed in their answer for them.
#
# To retire a rule, delete the line and delete its fixture. To add one, add the
# line and add a fixture that only the new rule catches; the check refuses to run
# with a rule that nothing proves works.
#
# ## Why so few batch-processing rules
#
# There used to be eleven, banning mapper, reducer, combiner, partitioning,
# shuffle, emit, intermediate pairs, the two-stage phase names and grouping by
# key. GLOSSARY.md defines those words for the students, and a glossary is the
# one document that has to name a thing to define it. Banning the vocabulary
# outright meant the manual could not use a word correctly even where it meant
# something else entirely — `emit` for what the wire does with an event, or a
# reducer as an illustrative workload in a cost model.
#
# So the vocabulary is allowed and the *example* is not. What is forbidden is the
# manual working the assignment through, and shapes.txt catches that: terms that
# are innocent alone and damning together. The two rules left here name the
# assignment and its canonical worked example, which are never innocent.

# ── the batch-processing assignment ──────────────────────────────────────────
map[[:space:]_-]*reduce:::the name of the assignment
\bword[[:space:]_-]*count\b:::the canonical worked example of it
