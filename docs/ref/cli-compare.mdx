---

```bash
java -cp build/losim.jar losim.cli.Main compare <a.json> <b.json>
```

<Warning>
This answers **"are these two the same simulator?"** Use it to check that a laptop,
the devcontainer, and a Codespace produce the same result. CI uses the same check.
Use [comparing designs](/simulate/comparing-designs) for design comparisons.
</Warning>

<Note>
`losim diff` is refused and the message names `compare`. The command takes two
**results**. A simulation produces one result; compare two designs by simulating
each one.
</Note>

## Field comparison

Results vary because they use real threads, a real wall clock, and no simulated
scheduler. Two simulations of one file on one host differ in durations and many
byte counts. Text comparison would report expected variation as a failure.

The command therefore compares structural fields separately from measurements.

## Structural fields

A difference here means that the two environments are not running the same simulator.

| | |
|---|---|
| `schema` | the trace schema version |
| `meta.simulation`, `entry`, `seed`, `scale`, `unit`, `count`, `telemetry`, `mode`, `schemaVersion`, `trusted`, `completed` | |
| what each **event kind carries** | the keys each kind's `detail` holds |
| what each **span kind is labelled** | |
| sampled channels | which `<node>.<metric>` channels exist |
| nodes | which nodes existed |
| **what each resource is a function of** | the attribution for the program |
| what the engine refused | |

<Note>
Event kinds are compared by **what each carries**, not by which kinds occurred. A
`queue_wait` depends on host contention, so its count may differ between hosts.
</Note>

## Measurements

| | |
|---|---|
| `meta.durationRefMs` | |
| `meta.loaded` | |
| the run size the engine chose | |
| every fitted exponent | |

`meta.loaded` records what `Load` produced **at the rung this run measured**. The
rung depends on the host heap, so a smaller host may measure and load fewer units.
It is a measurement rather than a structural field.

A Codespace is slower than a laptop, and that is what host calibration is for.

## Output

```
build/parity/traces-runner/t10.json
build/parity/traces-codespace/t10.json

  same    schema
  same    meta.simulation
  same    meta.entry
  same    meta.scale
  same    meta.loaded
  same    what each event kind carries
  same    what each span kind is labelled
  same    sampled channels
  same    nodes
  same    what each resource is a function of
  same    what the engine refused
  host    meta.durationRefMs: 4820 against 6113
  host    run size chosen: 8000 against 8000
  host    exponent of memoryMb: 1.013 against 1.011
```

Exit code is non-zero when a **structural** aspect differs.

## Schema changes

`schema` is compared first and, when it differs, alone:

```
  DIFFER  schema
            2
            4

  These traces use different formats. The remaining fields cannot be compared.
```

Everything below it is read against a shape both files are assumed to share. A
Traces written by losim 2 and losim 3 use different channel and span names, so the
command stops after reporting the schema difference.
