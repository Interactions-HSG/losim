## Families

<Columns cols={2}>
  <Card title="a1 — narrow" icon="compress">
    The only family here with **one** core. A node handles one call at a time, and
    declared work takes twice as long as on the reference node. Add an `a1.medium`
    to a pool of `c5.large`s to test whether placement responds to the difference.
  </Card>
  <Card title="m5 — balanced" icon="scale-balanced">
    The default balanced family. Use it when the node configuration is not the
    subject of the simulation.
  </Card>
  <Card title="c5 — compute" icon="gauge-high">
    More cores and less memory than `m5`. `c5.4xlarge` provides sixteen threads in
    one pool, which makes within-node contention visible.
  </Card>
  <Card title="r5 — memory" icon="memory">
    Twice the memory of an `m5` with the same core count. Use it for designs that
    retain substantial data.
  </Card>
</Columns>

`i3.large` provides 475 GB of storage; the other types provide 8 to 32 GB.

## Values derived from the row

<ParamField path="vCPU" type="int">
  The size of the node's **thread pool** and its speed relative to the reference
  node: `machineFactor = 2 ÷ vcpu`. A `c5.4xlarge` runs an 8 refMs handler in 1
  refMs; an `m5.large` takes 8, and an `a1.nano` takes 16.
</ParamField>

<ParamField path="memory" type="MB">
  The default memory cap, enforced against the retained-heap walk. A node can
  override it with `memoryMb:` at `scale: 1`; above `scale: 1`, the engine solves
  for the cap.
</ParamField>

<ParamField path="storage" type="GB">
  The default disk cap. `wroteDisk` throws when the cap is exceeded.
</ParamField>

<ParamField path="$/hour" type="double">
  The on-demand rate used by the bill's **capacity** bucket. A node that received a
  `spot_notice` is billed at the spot rate, which is 70% off by default.
</ParamField>

<Note>
**The instance row owns the rental price.** The rate is part of the node definition,
alongside vCPUs and memory, rather than a separate course setting.
</Note>

## Choose instances

<Tip>
A mixed pool exposes differences between node types:

```yaml
workers:
  count: 4
  prefix: w
  instance: c5.large
  runs: { Thumbnailer: src/lab/Shrinker.java }
  overrides:
    w3: { instance: a1.medium }
```

This pool has three compute nodes and one slower node. It lets the simulation test
whether the coordinator notices the difference and responds to it.
</Tip>
