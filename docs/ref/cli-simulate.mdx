---
title: "dissaly simulate"
description: "Simulate one file and write the trace everything downstream reads."
icon: "terminal"
---

```bash
./dissaly simulate <simulation.yaml> [options]
```

The wrapper written by `dissaly adopt` resolves the simulator. Without the wrapper,
run the command directly:

```bash
java -cp "$(cat build/losim/classpath)" \
     losim.cli.Main simulate thumbs.yaml --out build/thumbs.json
```

<Note>
`dissaly run` is refused and the message names `simulate`. One simulation produces
one **result**. Compare two designs with [`dissaly compare`](/ref/cli-compare).
</Note>

## Options

<ParamField path="--cp <paths>" type="path list" default="build/losim/classes">
  Colon-separated **directories** where your services are compiled to. losim loads
  the classes the `runs:` paths resolve to from here, and the trust verifier reads
  their bytecode from here.

  Defaults to where `./dissaly build` compiles to, when that directory is there. It
  has to: the classpath the build resolves is the simulator and gRPC and
  deliberately not your own output, so the JVM running this has never heard of the
  class a `runs:` path names.

  losim does not walk a jar. If you point this option at one, the run records that
  no classes were checked:
  *"A jar is not walked; point --cp at the directory the project compiles to."*
</ParamField>

<ParamField path="--out <file>" type="path" default="build/<name>.json">
  Where to write the trace. Parent directories are created.

  <Tip>
  Point it at **`build/results/`** and the viewer finds the result automatically:

  ```bash
  --out build/results/mine.json
  ```

  [Opening a trace in the viewer ->](/viewer/opening-a-trace)
  </Tip>

  Simulate several files into one `--out` directory and they are all in the picker,
  side by side.
</ParamField>

<ParamField path="--seed <n>" type="long">
  Overrides the simulation's `seed`. It changes failure timing, RPC failures, network
  jitter, packet loss, and workloads generated by `Load`.
</ParamField>

<ParamField path="--workers <n|+n>" type="int">
  Resize every pool that has more than one node. `8` sets them to eight; `+2` adds
  two to each. Use this to measure the effect of adding replicas without editing the file.
</ParamField>

<ParamField path="--overlay <file>" type="path">
  Apply a second file's failures and network settings to this simulation. It may set
  `seed`, `network`, `retries`, and `failures:` for nodes in the base file.

  A node named in the overlay has its whole `failures:` list **replaced**. The node
  definitions and Java files remain those in the base simulation.
</ParamField>

<ParamField path="--telemetry <level>" type="FULL | NO_PAYLOAD | OFF" default="FULL">
  `FULL` records every call's argument and result. `NO_PAYLOAD` keeps events, spans,
  and series without rendering payloads. `OFF` records no telemetry.
</ParamField>

<ParamField path="--no-view" type="flag">
  Write the trace and stop. At a terminal, `simulate` otherwise opens the viewer on
  what it just simulated and keeps it open.
</ParamField>

## Environment

<ParamField path="LOSIM_DEBUG" type="set / unset">
  When set, an exit-code-3 failure prints its stack trace as well as its message.
  This switch keeps stack traces out of ordinary command output.
</ParamField>

## Output

At `scale: 1`:

```
thumbs.yaml  seed 7  completed in 2416 refMs
  1044 events, 322 spans, 68 series -> build/thumbs.json
```

The output may also include the failure that ended the run, resource-limit lines,
and the trust block.

Above `scale: 1` it prints the plan, the fitted laws, the refusals, and both sizes
for every measurement. [Above scale 1 ->](/simulate/scaled)

## Exit codes

| | |
|---|---|
| `0` | `Job.Run` completed |
| `1` | it did not complete, threw, exceeded two minutes of real time, or had no feasible size |
| `2` | the simulation is invalid; nothing ran |
| `3` | something went wrong inside losim |

<Note>
An incomplete run still writes a trace with `meta.completed: false` and
`meta.failure` naming the cause.
</Note>
