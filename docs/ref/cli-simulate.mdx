---
title: "losim simulate"
description: "Simulate one file and write the trace everything downstream reads."
icon: "terminal"
---

```bash
./losim simulate <simulation.yaml> [options]
```

The wrapper `losim adopt` wrote resolves the simulator, so there is no classpath to
assemble. Without it, the same thing by hand:

```bash
java -cp "$(cat build/losim/classpath)" \
     losim.cli.Main simulate thumbs.yaml --out build/thumbs.json
```

<Note>
`losim run` is refused rather than aliased, with `simulate` named. A simulation is
simulated and yields one **result**; there is no comparison inside one, which is
what `run` left open. Two designs are two files and [`losim
compare`](/ref/cli-compare).
</Note>

## Options

<ParamField path="--cp <paths>" type="path list" default="build/losim/classes">
  Colon-separated **directories** where your services are compiled to. losim loads
  the classes the `runs:` paths resolve to from here, and the trust verifier reads
  their bytecode from here.

  Defaults to where `./losim build` compiles to, when that directory is there. It
  has to: the classpath the build resolves is the simulator and gRPC and
  deliberately not your own output, so the JVM running this has never heard of the
  class a `runs:` path names.

  A jar is not walked. If you point this at one, the run happens and the trace
  records that nothing was checked:
  *"A jar is not walked; point --cp at the directory the project compiles to."*
</ParamField>

<ParamField path="--out <file>" type="path" default="build/<name>.json">
  Where to write the trace. Parent directories are created.

  <Tip>
  Point it at **`build/results/`** and the viewer picks the result up with no
  arguments and no configuration:

  ```bash
  --out build/results/mine.json
  ```

  [Opening a trace in the viewer ->](/viewer/opening-a-trace)
  </Tip>

  Simulate several files into one `--out` directory and they are all in the picker,
  side by side.
</ParamField>

<ParamField path="--seed <n>" type="long">
  Overrides the simulation's `seed`. Everything drawn from the seed changes with it:
  when drawn failures fire, which calls an rpc failure hits, network jitter, packet
  loss, and — through `Losim.current().seed()` — a workload your `Load` generates.
</ParamField>

<ParamField path="--workers <n|+n>" type="int">
  Resize every pool that has more than one node. `8` sets them to eight; `+2` adds
  two to each. For asking what one more replica buys without editing the file.
</ParamField>

<ParamField path="--overlay <file>" type="path">
  Lay a second file's weather over this one. It may set `seed`, `network`,
  `retries`, and `failures:` on nodes the base file already has — and nothing else.

  A node named in the overlay has its whole `failures:` list **replaced**, not added
  to. The system itself stays the one that was written: a simulation whose nodes had
  been swapped out underneath it is no longer a run of that design, and an examiner
  would be asking about somebody else's system.
</ParamField>

<ParamField path="--telemetry <level>" type="FULL | NO_PAYLOAD | OFF" default="FULL">
  `FULL` records everything including every call's real argument and real result.
  `NO_PAYLOAD` keeps events, spans and series but renders nothing. `OFF` keeps
  nothing at all — the baseline the other two are measured against.
</ParamField>

<ParamField path="--no-view" type="flag">
  Write the trace and stop. At a terminal, `simulate` otherwise opens the viewer on
  what it just simulated and keeps it open.
</ParamField>

## Environment

<ParamField path="LOSIM_DEBUG" type="set / unset">
  When set, an exit-code-3 failure prints its stack trace as well as its message.
  Kept behind a switch so an ordinary run reads like a tool rather than like a
  crash.
</ParamField>

## Output

At `scale: 1`:

```
thumbs.yaml  seed 7  completed in 2416 refMs
  1044 events, 322 spans, 68 series -> build/thumbs.json
```

Plus, when they apply: the failure that ended it; one line per node that ran out of
memory or disk; and the trust block.

Above `scale: 1` it prints the plan, the fitted laws, the refusals, and both sizes
for every measurement. [Above scale 1 ->](/simulate/scaled)

## Exit codes

| | |
|---|---|
| `0` | `Job.Run` completed |
| `1` | it did not — it threw, or was still running after two minutes of real time; or the engine found no feasible size |
| `2` | the simulation is wrong. Nothing ran. |
| `3` | something went wrong inside losim |

<Note>
A run that failed still writes its trace, with `meta.completed: false` and
`meta.failure` naming the cause. A run that failed is a result, not an absence of
one.
</Note>
