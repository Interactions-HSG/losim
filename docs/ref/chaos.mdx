---
title: "chaos"
description: "A standing chance of a bad day, rather than a scripted one."
icon: "dice"
---

```yaml
chaos:
  - kill:    { every: 800 refMs, among: workers }
  - freeze:  { every: 400 refMs, among: workers, for: 150 refMs }
  - degrade: { every: 600 refMs, among: w2,      factor: 3 }
```

<Note>
A scenario with a fault at 900 refMs teaches the cluster to survive 900 refMs. A rate
teaches it to survive **whenever**, which is the harder and more honest thing — and
it is why sweeps exist: one seed shows a design survived an afternoon, twenty show
it survives afternoons.
</Note>

## Only three kinds

`kill`, `freeze` and `degrade`. Anything else is refused:

```
thumbs.yaml:31: partition happens at a moment, not at a rate; put it under faults:
thumbs.yaml:33: chaos cannot 'explode'; it can kill, freeze or degrade
```

## Fields

<ParamField path="every" type="duration" required>
  The **mean** gap between events. Draws are exponential — `-ln(1 - u) x every` ;
  so the gaps vary the way real bad afternoons do rather than arriving on a metronome.
</ParamField>

<ParamField path="among" type="pool name or machine name" required>
  Which machines are eligible. A pool key (`workers`) or one machine's name (`w2`).
  Anything else is refused, and the message lists the pools this scenario has.

  Only **live** machines are candidates at the moment of the draw. If every eligible
  machine is already dead, nothing happens.
</ParamField>

<ParamField path="factor" type="double" default="2">
  For `degrade`.
</ParamField>

<ParamField path="for" type="duration" default="1000 refMs">
  For `freeze`. The thaw is scheduled at `at + for`.
</ParamField>

## In the trace

```json
{ "kind": "chaos", "vm": "w2",
  "detail": { "kind": "kill", "among": "workers", "atRefMs": 1843.2 } }
```

followed by the ordinary `kill`, `freeze` or `degrade` event for that machine — so a
reader can tell a scripted fault from a drawn one, and both are otherwise identical.

## A rate has no horizon

<Note>
Each firing draws the next one, so chaos keeps happening for as long as the run
does. There is nothing to overrun and no `over_horizon` event: a quiet second half
that looked exactly like a cluster behaving well used to be possible, and is not any
more.
</Note>

## Sweep it

Chaos placement is drawn from the seed, so a single run tells you about one
afternoon:

```java
for (long seed = 1; seed <= 20; seed++) {
    var r = Run.of(base.withSeed(seed), loader, Telemetry.Level.OFF);
    if (!r.completed()) System.out.printf("seed %2d  %s%n", seed, r.failure());
}
```


Report the spread, not the best run. [Sweeps ->](/run/sweeps)
