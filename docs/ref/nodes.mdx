```yaml
nodes:
  master:                       # one node, named by its key
    instance: m5.large
    zone: eu-central-1a
    runs: { dissaly.Job: src/RenderJob.java }

  workers:                           # a pool: w0 w1 w2 w3
    count: 4
    prefix: w
    instance: c5.large
    zone: [eu-central-1a, eu-central-1b]
    runs: { Thumbnailer: src/Shrinker.java }
    memoryMb: 2048
    diskMb: 8192
    failures:
      - { degrade: 3, per: 2 refSeconds }
    overrides:
      w3: { instance: a1.medium, memoryMb: 512, zone: eu-central-1c }
```

The configuration must contain at least one node, and **exactly one must run
`dissaly.Job`**.

## Services

```yaml
runs: { Thumbnailer: src/Shrinker.java }
```

A map from **service name** on the left to the implementing **`.java` file** on the
right.

The key is the gRPC service name and the value used by `peersServing("Thumbnailer")`.
Use a dotted name when the `.proto` has a package, such as `dissaly.Job` or
`render.Thumbnailer`. A key that disagrees with the class's service is refused.

The value is a path relative to the project root. It must end in `.java`, the file
must exist, and it must declare a type with its own name. dissaly checks all three
conditions **at load** before building, then loads the compiled class from
`dissaly build`.

<Note>
A path, not a class name, identifies the implementation. dissaly can check a path
before compiling, so a typo is reported during loading rather than after a full
build.
</Note>

A node without `runs:` still exists and listens, but offers no service.

### Longhand form

```yaml
runs:
  Thumbnailer:
    file: src/Shrinker.java
    failures:
      Thumbnail:
        - { status: UNAVAILABLE, per: 20 calls }
```

The shorthand is the same configuration with `file:` unwrapped. Expand it when the
node's copy of an RPC needs a failure rule. See [failures](/ref/failures).

## Keys

<ParamField path="instance" type="instance type" required>
  From the [catalogue](/ref/instances). It defines vCPU count, memory, disk,
  network, and the on-demand rate used by billing.
</ParamField>

<ParamField path="zone" type="string or list" default="default">
  A string for one node or a list for a pool. Pool zones are assigned **round robin**;
  `[a, b]` over four nodes gives `a b a b`.
</ParamField>

<ParamField path="runs" type="map of service to .java path">
  The services this node offers.
</ParamField>

<ParamField path="failures" type="list">
  Failure actions for this node: `kill`, `freeze`, `degrade`, `spotReclaim`,
  `partition`, `heal`, and `restart`. See [failures](/ref/failures).
</ParamField>

<ParamField path="count" type="int" default="0">
  Makes this key a **pool** of `count` nodes. Zero or absent means one node named by
  the key itself.
</ParamField>

<ParamField path="prefix" type="string" default="the pool's key">
  Nodes are named `prefix0` through `prefix{count-1}`. A pool called `workers` with
  `prefix: w` produces `w0 w1 w2 w3`, not `workers0`.
</ParamField>

<ParamField path="memoryMb" type="double" default="the instance type's">
  The memory cap, enforced against a retained-heap walk.
</ParamField>

<ParamField path="diskMb" type="double" default="the instance type's storage">
  The disk cap. `Dissaly.current().wroteDisk(bytes)` throws when it is exceeded.
</ParamField>

<ParamField path="overrides" type="map by node name">
  Per-node changes within a pool. Accepts `instance`, `zone`, `memoryMb`, `diskMb`,
  and `failures`, but not `runs:`; every pool node runs the same code.
</ParamField>

## Per-node differences

Use overrides to give individual pool nodes different conditions:

```yaml
overrides:
  w3: { memoryMb: 4 }                                     # cannot hold its share
  w2: { instance: a1.medium }                             # half the node its peers are
  w1: { failures: [ { kill: true, at: 900 refMs } ] }     # the one that dies
```

A mixed pool lets the master respond to capacity and failure differences.

An `overrides:` entry **replaces** the pool's `failures:` rather than adding to
them. A node with an override receives only the listed failure rules.

## Scale above 1

**Do not write caps.** Above `scale: 1`, the engine solves per-node, per-resource
caps so demand relative to capacity is preserved. The file defines the system's
*shape*; the engine selects its size. [Solving caps ->](/engine/solving-caps)

## Runtime node

| | |
|---|---|
| one in-process gRPC server | named after the node |
| one thread pool | sized to the instance's vCPU count, platform threads, never `directExecutor` |
| a memory cap | checked against a retained-heap walk every eighth sampler tick, and once at the end |
| a disk cap | checked on every `wroteDisk` |
| a zone | which decides latency, and which bytes are billed |
| one channel per peer | made once, owned by the node |
| a local store | `Dissaly.current().local()`, shared by every service on it, emptied by a restart |
