```bash
java -jar dissaly.jar adopt [<dir>] [--force] [--dirty]
./dissaly check [--root .]
```

The migration guide explains the process: [adopting a gRPC system](/start/adopt).

## `adopt`

| | |
|---|---|
| `<dir>` | the project to adopt. Default `.` |
| `--force` | overwrite files previously written by the command. Existing files are otherwise kept |
| `--dirty` | adopt a tree with uncommitted changes. Without it, the command refuses because it moves files with `git mv` |

The command never edits a `.java`. It moves `src/main/proto` to `proto/` and
`src/main/java` to `src/`. It writes `build.gradle.kts`, `./dissaly`, `AGENTS.md`,
`simulations/1-one-call.yaml`, and two lines of `.gitignore`. It moves
`build.gradle` to `build.gradle.bak` and prints the remaining work.

<Note>
The generated simulation names the files expected after the handler is split out.
Loading then reports the missing file and class instead of running the nested
`HelloWorldServer$GreeterImpl` implementation.
</Note>

### Exit codes

| | |
|---|---|
| `0` | adopted |
| `2` | it refused: a `pom.xml`, a multi-module build, nothing that looks like gRPC, or a dirty tree |

## `check`

`check` runs the same detector on a project that has already been adopted.

```
1 service, 1 rpc, 2 source files

  runs with an unreliable measurement
   1  GreeterImpl is nested inside another class
      src/io/grpc/examples/helloworld/HelloWorldServer.java:53
      the trust verifier walks a nested class together with its enclosing class.
      The enclosing server, channel, and static fields are then attributed to it.

  dead code
      src/io/grpc/examples/helloworld/HelloWorldServer.java
       :48    main(String[]) and its arguments  a node has no command line
       :26    addShutdownHook                   a node is killed by a fault, not by SIGTERM
```

It does not compile or run the project. It reports findings before the first
build.

The command exits 0 whether or not it finds anything. Findings describe migration
work; they are not command failures.

## What it reads

`adopt` reads source text rather than bytecode. It runs from `java -jar dissaly.jar`
without the project on the classpath. It reads the `.proto` for services, RPCs,
`stream`, and `idempotency_level`; each `.java` for implementations, nesting,
servers, channels, and dead code; and the build file for gRPC and protobuf
versions.

It skips `build/`, `gen/`, `out/`, `target/`, and hidden paths. Reports therefore
point to source files instead of generated `ImplBase` classes.
