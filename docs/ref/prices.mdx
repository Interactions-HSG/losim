```yaml prices/eu-central-1.yaml
region: eu-central-1
currency: CHF
spot_discount: 0.70
egress_per_gb: 0.0100                   # between zones, inside this region
egress_cross_region_per_gb: 0.0200      # to another region on this continent
egress_intercontinental_per_gb: 0.0900  # across an ocean
storage_per_gb_month: 0.1000
billing_minimum_seconds: 60
build_per_service_month: 250
sla_seconds: 10
late_penalty_per_second: 0.50
incident_per_rerun: 0.02
incident_per_lost_machine: 0.20
```

```bash
java -cp "$CP" dissaly.cli.Main bill build/thumbs.json --prices prices/eu-central-1.yaml
```

If the file is missing, dissaly uses the defaults above and reports that fact. Any key
not in this list is refused.

## Regions

There is one file per region. Billing is a **pure function of the trace**, so the
same run can be priced in all ten regions without running it again.

| file | provider | where | index | build / service / month |
|---|---|---|---|---|
| `us-east-1` | AWS | N. Virginia | 0.85 | 280 |
| `us-west-2` | AWS | Oregon | 0.88 | 300 |
| `eu-west-1` | AWS | Ireland | 0.95 | 240 |
| `eu-central-1` | AWS | Frankfurt | 1.00 | 250 |
| `ap-south-1` | AWS | Mumbai | 1.10 | 90 |
| `switzerlandnorth` | Azure | Zurich | 1.15 | 330 |
| `ap-northeast-1` | AWS | Tokyo | 1.25 | 260 |
| `australiaeast` | Azure | Sydney | 1.30 | 290 |
| `southafricanorth` | Azure | Johannesburg | 1.35 | 130 |
| `sa-east-1` | AWS | São Paulo | 1.45 | 120 |

The list contains representative regions rather than every region sold by either
cloud. They provide local, nearby, and distant pricing differences.

<Warning>
**These are estimates, not vendor list prices.** Egress and storage use the
Frankfurt baseline multiplied by the region index. `build_per_service_month` uses a
separate local-cost estimate.

The values are deliberately approximate. Use the **ratios** for comparisons. To use
current provider rates, replace the values in these files; no simulator code needs
to change.
</Warning>

## Distance rates

Traffic uses three paid distances and one free distance:

| link | rate | when |
|---|---|---|
| same zone | **free** | both nodes in `eu-central-1a` |
| same region | `egress_per_gb` | `eu-central-1a` -> `eu-central-1b` |
| same continent | `egress_cross_region_per_gb` | `eu-central-1a` -> `eu-west-1a` |
| across an ocean | `egress_intercontinental_per_gb` | `eu-central-1a` -> `ap-northeast-1a` |

The node's `zone` determines the distance, and dissaly reads the **region from the
zone name**. For example, `eu-central-1a` belongs to `eu-central-1`, while
`switzerlandnorth-1` belongs to `switzerlandnorth`.

The run records `egressMb` on each node by destination region
([nodes channel](/ref/nodes-channel)). The bill can then show up to three egress
lines instead of folding all traffic into one total.

<Note>
A zone dissaly does not recognize, such as `rack-3` or `left`, is treated as its own
region on an unknown continent. Traffic to it uses the **cross-region** rate rather
than an inferred ocean crossing.

dissaly does not validate zone names. Simulations may use any zone string.
</Note>

## Fields

<ParamField path="currency" type="string" default="CHF">
  Printed beside every figure. This field is cosmetic.
</ParamField>

<ParamField path="spot_discount" type="double" default="0.70">
  The discount applied to a reclaimable node. After `spot_notice`, billing uses
  `onDemand x (1 - spot_discount)`.
</ParamField>

<ParamField path="region" type="string" default="">
  The region represented by the rates. It identifies the price file on the bill.
  **Node location comes from the simulation, never from this field.**
</ParamField>

<ParamField path="egress_per_gb" type="double" default="0.01">
  Per GB to another zone **in the same region**. Traffic inside one zone is free.
</ParamField>

<ParamField path="egress_cross_region_per_gb" type="double" default="0.02">
  Per GB to another region **on the same continent**.
</ParamField>

<ParamField path="egress_intercontinental_per_gb" type="double" default="0.09">
  Per GB **across an ocean**. The default is nine times the in-region rate.
</ParamField>

<ParamField path="storage_per_gb_month" type="double" default="0.10">
  Applied to the worst node's disk usage, held for the period.
</ParamField>

<ParamField path="billing_minimum_seconds" type="long" default="60">
  The shortest period billed for a node. A run of 2 reference seconds is billed for
  one minute of capacity.
</ParamField>

<ParamField path="build_per_service_month" type="double" default="250.0">
  Monthly engineering cost for one service. It applies whether or not the service
  handles a call.
</ParamField>

<ParamField path="sla_seconds" type="double" default="10">
  The service level, in reference seconds.
</ParamField>

<ParamField path="late_penalty_per_second" type="double" default="0.50">
  Per second past the service level.
</ParamField>

<ParamField path="incident_per_rerun" type="double" default="0.02">
  Per `rpc_timeout`, for work redone after a node misses its deadline.
</ParamField>

<ParamField path="incident_per_lost_machine" type="double" default="0.20">
  Per `kill` or `spot_notice`. A node that **filled up**, through `oom` or
  `disk_full`, is charged **five times** this amount.
</ParamField>

## Outside the simulator

<Note>
The price list can be updated or **deliberately distorted for an exercise** without
changing the simulator. That is why it lives in `prices/`.

Billing reads the trace, so a different price list needs no re-run. A changed design
ranking indicates dependence on that price assumption.
</Note>

```yaml prices/expensive-egress.yaml
currency: CHF
egress_per_gb: 4.00
```

```bash
java -cp "$CP" dissaly.cli.Main bill build/a.json --prices prices/expensive-egress.yaml
java -cp "$CP" dissaly.cli.Main bill build/b.json --prices prices/expensive-egress.yaml
```

This tests whether moving data across zones for convenience is cheaper.

<Warning>
**Node rental cost is not defined here.** It belongs to the [instance
catalogue](/ref/instances), with the node's vCPUs and memory.
</Warning>
