```yaml
retries:
  - { method: Thumbnail, attempts: 3, backoff: 50 refMs, multiplier: 2 }
  - { method: Append,    attempts: 2, unsafe: true }
```

## Retry fields

<ParamField path="method" type="string" required>
  Matched against the methods served by the system:

  | form | example |
  |---|---|
  | the bare rpc name | `Thumbnail` |
  | fully qualified, **dotted** | `lab.Thumbnailer.Thumbnail` |
  | any dotted suffix | `Thumbnailer.Thumbnail` |
  | everything | `*` |

  A policy naming a method **no node serves** is refused.
</ParamField>

<ParamField path="attempts" type="int" required>
  Total attempts including the first. The value must be at least 1. A policy of 1
  makes no retry.
</ParamField>

<ParamField path="backoff" type="duration" default="0 refMs">
  The delay before the **second** attempt.
</ParamField>

<ParamField path="multiplier" type="double" default="1">
  Each subsequent backoff is multiplied by this. `backoff: 50 refMs, multiplier: 2`
  waits 50 before the second attempt and 100 before the third.
</ParamField>

<ParamField path="unsafe" type="boolean" default="false">
  Retry a method the schema does not declare safe. Set this only when the method is
  safe to run more than once despite its schema declaration.
</ParamField>

## Safety check

```
thumbs.yaml:22: retrying lab.Volley.Hit is refused — its .proto declares no
idempotency_level, so running it twice is not known to be safe. Declare
'option idempotency_level = IDEMPOTENT;' on the rpc if it is, or write
'unsafe: true' here if you mean to retry it anyway.
```

Either level satisfies it:

```proto
rpc Thumbnail (Split) returns (Thumbs) { option idempotency_level = NO_SIDE_EFFECTS; }
rpc Announce  (Health) returns (Empty) { option idempotency_level = IDEMPOTENT; }
```

<Note>
Retry policy belongs in the simulation file because it describes runtime behavior.
Retry safety belongs in the `.proto` because it describes the method. losim checks
both before making a call.
</Note>

## Retried and excluded

| retried | not retried |
|---|---|
| `UNAVAILABLE` | everything else — an `INVALID_ARGUMENT` will be invalid the second time too |
| `DEADLINE_EXCEEDED` | a call where a message already arrived |
| `RESOURCE_EXHAUSTED` | a cancelled call |
| `ABORTED` | any **streaming** call |
| `UNKNOWN` | |

<Note>
Only unary calls can be retried. Replaying a stream would require buffering it, with
an undeclared buffer size.
</Note>

## Attempt accounting

The retry interceptor sits **outside** the recording interceptor. Each attempt gets
its own span, byte count, loss draw, and liveness check. Retry accounting therefore
matches the work performed.

```json
{ "kind": "retry", "vm": "master", "detail": {
    "method": "lab.Thumbnailer.Thumbnail", "attempt": 1, "of": 3,
    "after": "DEADLINE_EXCEEDED", "backoffRefMs": 50.0 } }

{ "kind": "retry_done", "vm": "master", "detail": {
    "method": "lab.Thumbnailer.Thumbnail", "attempts": 3, "status": "OK" } }
```

`retry_done` appears only when there was more than one attempt. `unsafe: true` appears
on the `retry` event when the policy set it.

<Warning>
Every attempt shares the **same absolute deadline** from `CallOptions`. A growing
backoff can exhaust that deadline before all configured attempts run.
</Warning>
