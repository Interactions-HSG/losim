One run, one JSON file. Everything downstream reads it: the bill, the viewer, your
own assertions.

```json
{
  "schema": 4,
  "meta":     { … },
  "events":   [ … ],
  "spans":    [ … ],
  "series":   { "dtMs": 6.0, "t": [ … ], "channels": { … } },
  "nodes":    [ … ]
}
```

## The contract

<Warning>
**The trace is the interchange format, so its shapes are a contract.**

Event kinds and their keys are extended **only additively**. `spans` and `series`
are new top-level channels rather than changes to `events`, for exactly that reason.
The acceptance test is diffing a trace's event kinds and keys before and after a
change and finding it empty — which is also what
[`losim compare`](/ref/cli-compare) checks across environments.

`schema` is bumped only when a shape changes incompatibly. It is currently **4**.
</Warning>

<Note>
It has been bumped, and 3.0 is why. `nodes` became `nodes`, `meta.job` became
`meta.entry`, `failed` became `failed`, and the five span kinds became two. That
is the escape hatch the additive rule leaves open, and using it is what
`losim compare` reports first and alone when two traces disagree about it — rather
than a wall of differences with no cause named.
</Note>

## meta

```json
"meta": {
  "schemaVersion": 4,
  "scale": 1.0, "clockedAt": 20.0,
  "telemetry": "FULL",
  "simulation": "thumbs.yaml",
  "seed": 7,
  "entry": "coordinator",
  "unit": "frame",
  "count": 30000,
  "loaded": 30000,
  "completed": true,
  "durationRefMs": 2416,
  "trusted": true
}
```

| key | |
|---|---|
| `schemaVersion`, `clockedAt`, `telemetry` | written by the recorder |
| `simulation`, `seed` | what was asked for |
| `entry` | the node running `losim.Job` |
| `unit`, `count` | what one item is, and how many at **full** size — the file's own number |
| `loaded` | how many `Load` produced at the size this run measured. At `scale: 1` that is `count`; above it, `count` times the rung |
| `completed` | whether `Job.Run` returned normally |
| `failure` | present only when it did not, naming the cause |
| `durationRefMs` | the run's length, in reference milliseconds, rounded |
| `trusted` | present only when a classpath was given; `false` if anything was flagged |
| `mode`, `scale`, `projections` | present only above `scale: 1` |

## Ordering and rounding

`events` and `spans` are sorted by start time, so a reader can scrub. Every time and
every span detail is rounded to **three decimal places**; a `NaN` is written as `0`.

Figures in the `nodes` channel are megabytes to about a byte — six
decimal places, because three would be a kilobyte and a run small enough to be
measured in kilobytes would report every byte it moved as zero.

## Two traps

<Warning>
**`method` is dotted.** gRPC writes `render.Thumbnailer/Thumbnail`; the trace
writes `render.Thumbnailer.Thumbnail`, everywhere — `losim.Job.Run` included — so
everything downstream can split on a dot.

**Payload collections are truncated at 12 entries**, with a `"+1106 more"` marker.
The real count is *kept plus marker*, never the surviving length.
</Warning>

## Reading it

It is plain JSON with no custom types:

```python
import json
t = json.load(open("build/thumbs.json"))

assert t["schema"] == 4
print(t["meta"]["durationRefMs"], "refMs")
print(len(t["events"]), "events,", len(t["spans"]), "spans")
for m in t["nodes"]:
    print(f'{m["name"]:<12} {m["calls"]:>4} calls  {m["memoryMb"]:>8.2f} MB held')
```

losim reads it back with its own reader for `bill` and `compare`, and that path is
exercised by the reference suite — every assertion there reads the trace off disk,
because a build whose trace was unreadable would pass every check losim makes of
itself.
