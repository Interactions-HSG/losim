```json
{ "id": 15, "parent": 14, "vm": "w0", "kind": "handler",
  "label": "render.Thumbnailer.Thumbnail", "t0": 64.9, "t1": 78.9,
  "status": "OK", "units": 25,
  "detail": { "call": 14, "inBytes": 611432, "outBytes": 41206, "status": "OK" } }
```

| field | |
|---|---|
| `id` | unique within the run |
| `parent` | the span this one happened under; `0` means the root |
| `vm` | the node it happened on |
| `kind` | `rpc` or `handler` |
| `label` | the method |
| `t0`, `t1` | simulated milliseconds |
| `status` | `OK`, a gRPC status code, `FAILED`, `TIMEOUT` or `ABANDONED` |
| `units` | present only when the handler declared a count |
| `detail` | see below, sorted by key |

## Span types

<ResponseField name="rpc" type="on the caller">
  `detail` carries `to`, `bytes` (the request), `ms`, and `netRefMs` when the
  network had any latency. At `FULL`, `arg` and `result`.

  An undelivered call carries `delivered: false` and `why`.
</ResponseField>

<ResponseField name="handler" type="on the callee">
  Opened **under the caller's `rpc` span**. `detail` carries `call`, `inBytes`,
  `outBytes`, and `status`; failed calls also carry `error`. At `FULL`, it includes
  `arg` and `result`.
</ResponseField>

<Note>
Before 3.0, the trace also had `job`, `phase`, and `compute` spans. They represented
work started by a Java object outside an RPC.

The entry point is now a gRPC service. Its handler span **is** the root, labeled
`dissaly.Job.Run`, and other spans nest beneath it through the same parent metadata as
all other calls.
</Note>

## Root span

The span with `parent: 0` is the entry node's `handler`, labeled `dissaly.Job.Run`.
Its `t0` is zero and its `t1` is the simulation end.

A run that ends while a node is being killed can leave a handler at the root after
its caller span is gone. Such spans are intentional and carry `ABANDONED`.

## Parent propagation

<Note>
The caller sends the parent id in a **gRPC metadata header**. The callee reads that
header when it opens its handler span.

Using ambient context instead would attach every server span to the root and lose the
distributed call stack. A span unexpectedly attached to `0` indicates a channel
without dissaly's transport.
</Note>

## Print the tree

```python
import json, collections
t = json.load(open("build/thumbs.json"))
kids = collections.defaultdict(list)
for s in t["spans"]:
    kids[s["parent"]].append(s)

def show(pid, depth=0):
    for s in sorted(kids[pid], key=lambda s: s["t0"]):
        print(f'{"  " * depth}{s["vm"]:<12} {s["kind"]:<8} {s["label"]:<32} '
              f'{s["t0"]:8.1f} -> {s["t1"]:8.1f}  {s["status"]}')
        show(s["id"], depth + 1)

show(0)
```

## Gross and program durations

| | |
|---|---|
| **gross** | `t1 - t0`, open to close |
| **program** | gross minus whatever dissaly spent inside that window, on that thread |

`handler_end` events carry both as `grossMs` and `ms`. The scale engine fits the
**program** duration so instrumentation cost does not affect the projection.

## `ABANDONED`

```json
{ "status": "ABANDONED", "detail": { "why": "the run ended while this was in flight" } }
```

A run can end with work still in flight, such as a handler whose caller gave up or a
node killed mid-call. The span is closed explicitly so it is distinguishable from a
recorder that lost track.

This includes the root. If the entry node is killed, `dissaly.Job.Run` closes
`CANCELLED` and a `failed` event names the node.
