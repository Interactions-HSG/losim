The verifier reads your compiled classes **before anything runs**, walking outward
from the classes the simulation's `runs:` paths name. It never fails a run.

<Note>
Each rule identifies code that produces a **wrong number** while the run continues.
Code that reads the real clock still works, but it reports host time instead of
simulated time. The two differ by `k_time`.

The verifier reports the affected number as a lower bound and attaches the finding
to the node and resource it affects.
</Note>

## Trust rules

<AccordionGroup>
  <Accordion title="REAL_CLOCK — reads the real clock" icon="clock">
    Every duration dissaly knows is reference time divided by `k_time`. A handler that
    reads the host clock mixes host time with simulated time and reports the value
    returned by whichever clock the code used.

    `System.nanoTime`, `System.currentTimeMillis`, `Instant.now`, `LocalDate.now`,
    `LocalDateTime.now`, `LocalTime.now`, `OffsetDateTime.now`, `OffsetTime.now`,
    `ZonedDateTime.now`, `Year.now`, `YearMonth.now`, `Clock.system*`

    **Instead:** `Dissaly.current().clockMs()`.
  </Accordion>

  <Accordion title="REAL_SLEEP — sleeps in host milliseconds" icon="bed">
    This rule concerns the **unit** used for waiting. A hand-rolled backoff that
    sleeps 100 ms always sleeps 100 ms, regardless of `k_time`; at a compression of
    forty, that equals four thousand reference milliseconds.

    `Thread.sleep`, `TimeUnit.sleep`, `LockSupport.parkNanos`, `LockSupport.parkUntil`

    **Instead:** `Dissaly.current().sleep(refMs)`.

    Blocking on real work, such as a latch, future, `Object.wait`, or bare
    `LockSupport.park()`, is allowed. Its duration is set by the operation being
    awaited. Timed forms are also left alone,
    because the timeout is only spent when the wait fails and a static check cannot
    see which run that is.
  </Accordion>

  <Accordion title="UNATTRIBUTED_THREAD — work on a thread the node did not create" icon="ghost">
    Every thread in a node's pool belongs to that node, which allows dissaly to
    attribute allocation. Work on a thread outside the pool has no node attribution
    and uses no node's modeled cores.

    `Thread.start`, `Thread.ofVirtual`, `Thread.startVirtualThread`, `Executors.*`,
    `ForkJoinPool.*`, `CompletableFuture.supplyAsync`, `CompletableFuture.runAsync`,
    `*.parallelStream`, `java.util.stream.*.parallel`

    Virtual threads use this rule because they have the same attribution problem as
    other threads outside a node's pool. Switching to a platform thread does not
    change that problem.

    **Use this approach:** spread work by **calling more nodes** and let each node's
    pool serve several calls concurrently. Raw threads are allowed. The verifier
    flags work that has no node attribution.
  </Accordion>

  <Accordion title="FILE_IO — writes to a real disk" icon="hard-drive">
    dissaly accounts disk through `Dissaly.current().wroteDisk(n)` and caps it per
    node. Bytes written past that limit bypass the cap and every projection of it.
    They are written to the host, outside the one-node boundary.

    `java.nio.file.Files.*`, `FileOutputStream.*`, `FileInputStream.*`,
    `FileWriter.*`, `FileReader.*`, `RandomAccessFile.*`, `File.delete`, `File.mkdir`,
    `File.mkdirs`, `File.createNewFile`, `File.renameTo`
  </Accordion>

  <Accordion title="OUTSIDE_THE_JVM — reaches outside the JVM" icon="globe">
    *On one node* is the boundary used by the model. Anything that leaves the JVM
    falls outside simulation, measurement, and cross-host reproducibility.

    `java.net.Socket.*`, `ServerSocket.*`, `DatagramSocket.*`, `URL.openStream`,
    `URL.openConnection`, `java.net.http.*`, `SocketChannel.*`,
    `ServerSocketChannel.*`, `ProcessBuilder.*`, `Runtime.exec`
  </Accordion>

  <Accordion title="OWN_CHANNEL — a channel or server the system did not make" icon="plug">
    dissaly's interceptors run on both sides of every call. They record latency, loss,
    partitions, cost, spans, and byte counts. A channel built by hand lacks these
    interceptors, so its calls produce no corresponding trace data.

    `ManagedChannelBuilder.*`, `ServerBuilder.*`, `Grpc.newChannelBuilder*`,
    `Grpc.newServerBuilder*`, `io.grpc.inprocess.*`, `io.grpc.netty.*`,
    `io.grpc.okhttp.*`

    **Instead:** `Dissaly.current().channelTo(peer)` or `here.channelTo(node)`.

    <Note>
    A [level-3 debugging harness](/write/debugging) uses these classes correctly
    because it has no simulation. Keep such code in a
    test source set that no service or job references, and the walk never reaches it.
    </Note>
  </Accordion>

  <Accordion title="SHARED_STATE — mutable state in a static field" icon="share-nodes">
    A static field is one field for the whole system, so a system of eight "nodes"
    holding a static map holds **one map**. Every node's figure then includes the
    shared value.

    Constants are separate from mutable shared state. `static final String[] WORDS =
    {"a", "the"}` is a table and is not flagged. `static final Map M = new
    HashMap<>()` is one map for eight nodes and is flagged. The verifier reads the
    class initializer to distinguish these cases.
  </Accordion>

  <Accordion title="MACHINES_TOUCHING — one node reaching into another" icon="hand">
    A static handle on another node's service is a modelling error. The call crosses
    no network, waits out no latency, survives a partition, and keeps working after
    the node at the other end is killed.
  </Accordion>
</AccordionGroup>

## Unflagged behavior

<Note>
Unseeded `Random`, `Math.random`, and identity-hash iteration order are allowed.
Runs are not reproducible, so use a sweep of seeds to measure their variation.

</Note>

## Consequences of each flag

Each rule carries a flag, and each flag names the measured resources it makes
meaningless:

| flag | consequence | undermines |
|---|---|---|
| `timeline` | its timeline is not projectable | `makespanRefMs` |
| `memory` | its memory figure is a lower bound | `memoryMb`, `allocMb` |
| `disk` | its disk figure is a lower bound | `diskMb` |
| `wire` | its wire bytes are a lower bound | `wireMb` |
| `isolation` | its figures are not only its own | **all of them** |

Above `scale: 1`, the caveat is printed **beside the projection it undermines**. An
error bar describes fit quality; it does not establish that the measured value was
valid.

## Nested classes inherit enclosing-class findings

The rules are applied to a class **and every class it is declared inside**. So a
service written as a nested class carries whatever its enclosing class does.

That is the finding most likely to surprise somebody who has adopted an
existing project, because the grpc-java quickstart puts the handler exactly there:

```java
public class HelloWorldServer {                     // a server, a logger, a pool
  static class GreeterImpl extends GreeterGrpc.GreeterImplBase { … }
}
```

Placed as it stands, every run reports

```
srv  built its own channel or server, which no interceptor is attached to
```

The node's wire figures are marked, although the handler itself does nothing wrong.
**Move the service to a file of its own.** See the [adoption page](/start/adopt).

<Note>
The enclosing-class walk is intentional. A handler that reaches an enclosing class's
static field shares state across nodes, and the walk detects it.
</Note>

## Generated code is skipped

protoc's output often matches these rules because a `*Grpc` class holds six mutable
statics. The verifier recognises generated code through protobuf's superclass and
grpc-java's `@GrpcGenerated`.
