Simulation durations use **reference-node time** and must include a unit.

```yaml
at:          900 refMs
backoff:     50 refMs
crossZone:   3 refMs
```

## Accepted spellings

| | |
|---|---|
| `refMs`, `refms` | reference milliseconds |
| `refSeconds`, `refSec`, `refS`, `refs` | reference seconds, multiplied by 1000 |

The number may have a decimal point, and whitespace before the unit is optional:
`0.5 refMs`, `2refSeconds` and `900refMs` are all accepted.

## Bare durations are refused

```yaml
at: 900        # refused
at: 900ms      # refused
at: "900 ms"   # refused
```

```
thumbs.yaml:24: '900' does not say what kind of time it is. Durations are
reference-node time: write '900 refMs' or '900 refSeconds'. A bare number would
be ambiguous between the simulated world and your afternoon, and those differ by
k_time.
```

<Note>
**Why this is refused.** A run is compressed by `k_time`, a global factor that is
not known when a duration is written. A bare `900` could mean 900 milliseconds in
the simulated world or 900 wall-clock milliseconds. At 40x, those values differ
by a factor of forty.

Writing `refMs` removes the ambiguity.
</Note>

## Reference node

The reference node has two vCPUs and no competing work. A duration in `refMs`
states how long the work takes on that node. The statement remains the same when
the work runs on another node:

```
actual wall time  =  refMs x (2 / vcpu) x degradeFactor / k_time
```

| | |
|---|---|
| a 2-vCPU node | x1 |
| a 4-vCPU node | x0.5 |
| a 16-vCPU node | x0.125 |
| a node under `degrade: factor: 4` | x4 on top |

<Warning>
The multiplication applies to **work**, which is what `simulatedDuration:`
declares. It does not apply to waiting. A slower node computes for longer, but a
scheduled wait does not stretch, so
`Losim.current().sleep(refMs)` is divided by `k_time` and nothing else.
</Warning>

## Java durations

Two places, and both are reference time as well:

```java
Losim.current().sleep(200);                                   // 200 refMs
stub.withDeadlineAfter(2_000, TimeUnit.MILLISECONDS);         // 2000 refMs
```

The deadline uses milliseconds because that is gRPC's API. losim divides the
remaining time by `k_time` in the client interceptor, where the deadline's intent
is still available.

`Thread.sleep(200)` is 200 wall-clock milliseconds and is not affected by `k_time`.
The verifier flags it.
