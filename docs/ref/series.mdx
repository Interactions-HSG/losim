```json
"series": {
  "dtMs": 6.0,
  "t": [0.0, 6.0, 12.0, 18.0, …],
  "channels": {
    "w0.busyPct":  { "vm": "w0", "metric": "busyPct", "form": "runs",
                     "ticks": 402, "runs": [[0.0, 11], [100.0, 46], [50.0, 8]] },
    "w0.memCapMb": { "vm": "w0", "metric": "memCapMb", "form": "constant",
                     "ticks": 402, "value": 4096.0 },
    "w0.retainMb": { "vm": "w0", "metric": "retainMb", "form": "raw",
                     "ticks": 402, "raw": [0.0, 0.12, 1.44, …] }
  }
}
```

Channels use the key `"<vm>.<metric>"`. Every channel shares `t`, the simulated
times spaced by `dtMs`.

## Series data

<Note>
A change log records transitions and can miss a system that remains stuck. Series
make trace size follow run **duration** rather than activity, so a frozen system
remains observable.

The sampler starts at half a real millisecond and **thins as it goes**. When the
trace fills, it drops half the samples and doubles the interval. The number of
ticks stays bounded across runs of different lengths.
</Note>

The sampler runs on **its own thread**, not a node pool thread, so its work is not
included in the counters it reads.

## Metrics

| metric | |
|---|---|
| `allocMb` | cumulative allocation by this node's threads, losim's own subtracted |
| `retainMb` | what the node is holding now — the retained-heap walk |
| `memCapMb` | its memory cap |
| `memPct` | `retainMb / memCapMb x 100` |
| `diskMb` | bytes declared through `wroteDisk`, cumulative |
| `diskPct` | against the disk cap |
| `inflight` | handlers **using** a core |
| `queued` | handlers **waiting** for one |
| `vcpu` | the node's core count |
| `busyPct` | `inflight / vcpu x 100`, capped at 100 |
| `alive` | 1 or 0 |
| `frozen` | 1 or 0 |
| `degraded` | the current degrade factor, 1 when none |
| `bytesInMb`, `bytesOutMb` | cumulative |

<Warning>
`retainMb` **steps rather than glides**. A heap walk costs about 0.06 microseconds
per object, so a busy node is walked every eighth tick rather than every tick.
</Warning>

## Encodings

Each channel uses the smallest of three encodings. Many channels stay constant or
change in long runs.

<ResponseField name="constant" type="every tick is the same value">
  ```json
  { "form": "constant", "ticks": 402, "value": 4096.0 }
  ```
</ResponseField>

<ResponseField name="runs" type="run-length encoded">
  ```json
  { "form": "runs", "ticks": 402, "runs": [[0.0, 11], [100.0, 46]] }
  ```
  Each pair is `[value, howManyTicks]`.
</ResponseField>

<ResponseField name="raw" type="one number per tick">
  ```json
  { "form": "raw", "ticks": 402, "raw": [0.0, 0.12, 1.44, …] }
  ```
</ResponseField>

Choosing the smallest encoding can reduce the trace by about two orders of
magnitude.

<Note>
Samples are quantized before encoding: `…Pct` to one decimal place and `…Mb` to
two. Flat stretches can then form runs.

The `nodes` channel remains separate so fitted laws use unrounded measurements.
</Note>

## Decode a channel

```python
def channel(t, key):
    c = t["series"]["channels"][key]
    if c["form"] == "constant":
        return [c["value"]] * c["ticks"]
    if c["form"] == "runs":
        out = []
        for value, n in c["runs"]:
            out += [value] * int(n)
        return out
    return c["raw"]

import json
t = json.load(open("build/thumbs.json"))
times = t["series"]["t"]
busy  = channel(t, "w0.busyPct")
for at, b in list(zip(times, busy))[:10]:
    print(f"{at:8.1f}  {'#' * int(b / 5):<20} {b:5.1f}%")
```
