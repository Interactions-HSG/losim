description: "What each rpc costs on the reference machine, under the class that serves it."

```yaml
takes:
  Shrinker:
    Thumbnail: { refMs: 3, refNsPerUnit: 240000 }
    Capacity:  { refMs: 1 }
```

A key is a class `runs:` names; under it, an rpc that class serves. Both numbers
default to `0`, and an rpc nobody prices takes **no time** — deliberately, rather
than a made-up amount.

<ParamField path="refMs" type="number" default="0">
  What one call takes **regardless of what is in it** — the fixed part. Known before
  the handler runs, and slept before it.
</ParamField>

<ParamField path="refNsPerUnit" type="number" default="0">
  What each record processed adds, in reference **nanoseconds**. The handler
  declares the count with `Losim.current().units(n)`, and this part is slept
  **after the body returns**, before the response leaves — because a caller waits
  for work that has not finished, and by then the handler has said how much there
  was.
</ParamField>

<Note>
Plain numbers here, where everywhere else a duration has to say what kind of time
it is. The key already says it: `refMs` is reference milliseconds and
`refNsPerUnit` reference nanoseconds, so `3 refMs` under a key called `refMs`
would be the unit written twice.
</Note>

## Why the class and not the rpc

`retries:` names a method — `lab.Worker.Map` — because retrying is a decision about
a *call*. A duration is a property of the *code*: two implementations of one rpc,
placed on two machines, is how one design is compared with another, and a table
keyed on the rpc would say they take the same time.

So the key is what `runs:` says. Rename the class in `runs:` and the scenario stops
loading until the table follows.

## In the scenario, not in the Java

This used to be an annotation on the handler. It is not, and **nothing in a
system a student writes names losim at all** — the handlers are plain gRPC, they
compile with losim off the classpath, and they unit-test without it.

What that gives up is drift: an annotation followed a renamed method and a table
does not. So the table is checked against what the fleet actually serves, before
anything runs:

```
thumbs.yaml:31: takes names 'Shrinker Thumbnial', and Shrinker serves no rpc of
that name. It serves Capacity, Thumbnail. A cost that belongs to nothing is a
method that quietly takes no time, so it is a refusal rather than a warning.
```

A fleet that prices **nothing** is not refused — an unpriced rpc is a legitimate
thing — but it is said out loud in the trace, because a run where every call is
instant has no queueing, no contention and no critical path, and from the outside
looks like a design that is simply very fast.

## The sleep formula

```
refMs × (2 ÷ vcpu) × degradeFactor ÷ k_time
```

Reference-machine time is two vCPUs running alone. So a 4-vCPU machine takes half as
long, a machine under `degrade: factor: 4` takes four times as long, and the whole
run is compressed by `k_time`.

## Declared, not measured

losim shrinks the workload **and** the machines by the same factor, so memory and
bytes survive it honestly. Time does not, because the host's CPU is not shrunk — it
runs at full speed on a fraction of the data, so every handler is genuinely instant.
Without a declared duration there is no queueing, no contention, no deadline
pressure and no critical path.

Measuring instead does not work at this scale: handler durations at probe size sit
inside the host's own jitter, where the fitted time exponent moves by 0.25 between
seed sets of an identical workload.

## `takes:` versus `sleep`

| | `takes:` | `Losim.current().sleep(refMs)` |
|---|---|---|
| what it is | declared **work** | a declared **wait** |
| fixed per rpc? | yes, it is a table | no, the program decides |
| stretches on a slow machine? | **yes** | no |
| occupies a vCPU? | **yes** | no |

Measured at 40× on a machine at half speed: a declared 500 takes 1019 refMs and
`sleep(500)` takes 596. A backoff that grows with the attempt cannot be written in
a table at all, which is the other half of why both exist.

## The floor

The clock cannot express a duration finer than about **0.05 ms** of real time. Below
that a cost is *owed* rather than slept, and the ledger settles it later — good for
about fifty times below the floor. Past that the engine refuses to project from it:

```
this run is clocked at 40x real time, and lab.Thumbnailer.Capacity costs 0.0004
refMs — 6x below what the sleep debt can still settle at that compression, so its
timings would drift rather than be owed. Give that cost site more to do, or lower
the scale: at scale 1 the clock runs at 20x.
```
