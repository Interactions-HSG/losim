The simulation file stores the system, failures, and timing. It references code by
`.java` path, which lets runs vary without changing source files.

## Top-level keys

```yaml
seed: 7                    # long,   default 1
scale: 5000                # number, default 1, at least 1

nodes:             { ... }   # required, at least one
input:             { ... }
network:           { ... }
retries:           [ ... ]
simulatedDuration: { ... }
```

These are the accepted top-level keys. Other keys are refused with their source
line. The node running `losim.Job` starts the work, so there is no `job:` key.
`scale` selects direct or modeled execution, and `failures:` is nested under its
target instead of using `faults:` or `chaos:`.

<ParamField path="seed" type="long" default="1">
  Everything random draws from it: when failures fire, network jitter, packet
  loss, which calls an rpc failure hits, and your own workload through
  `Losim.current().seed()`. `--seed` overrides it.
</ParamField>

<ParamField path="scale" type="number" default="1">
  How many times bigger the design is than the simulation measuring it. At 1 there
  is no model: the input is exactly what `input:` says and every number is what
  happened. See [scale](/ref/scale).
</ParamField>

<ParamField path="nodes" type="map" required>
  The system. One entry is one node or, with `count:`, a pool. Exactly
  one node in the file must run `losim.Job`. See [nodes](/ref/nodes).
</ParamField>

<ParamField path="input" type="map">
  The workload at full size: a `source:`, what one `unit:` is, and how many.
  Omitted entirely, the simulation runs one unit of nothing in particular. See
  [input](/ref/input).
</ParamField>

## Validation

<Warning>
The loader refuses invalid configuration with the source line: an unknown key, an
unknown instance type, a duration without a unit,
an invalid `runs:` value, a
partition aimed at an absent node, a failure that specifies both a time and a rate,
an unsupported retry policy, or duplicate node names.

Nothing runs, and the exit code is 2.
</Warning>

The loader does not load classes, so it cannot check three runtime relationships:
whether the class in a file really serves the service it is filed under, whether
that service has an rpc a `failures:` block names, and whether it has one
`simulatedDuration:` prices. Those are asked once the nodes are up and their
servers can answer, and refused there with the line from this file. See
[refusal handling](/simulate/refusals).

## Example

```yaml
seed: 7
scale: 500

nodes:
  master:
    instance: m5.large
    zone: eu-central-1a
    runs: { losim.Job: src/RenderJob.java }

  workers:
    count: 4
    prefix: w
    instance: c5.large
    zone: [eu-central-1a, eu-central-1b]
    runs: { Thumbnailer: src/Shrinker.java }
    failures:
      - { degrade: 4, per: 2 refSeconds }
    overrides:
      w3:
        instance: a1.medium
        memoryMb: 512
        failures:
          - { kill: true, at: 900 refMs, restartAfter: 400 refMs }
          - { partition: master, at: 1600 refMs }
          - { heal: master, at: 2400 refMs }

input:
  source: data/frames/
  unit:   frame
  count:  30000

network:
  sameZone:  0.4 refMs
  crossZone: 3 refMs
  jitter:    0.5 refMs
  loss:      0.01

retries:
  - { method: Thumbnail, attempts: 3, backoff: 50 refMs, multiplier: 2 }

simulatedDuration:
  src/Shrinker.java:
    Thumbnail: { fixed: 3 refMs, perUnit: 240000 refNs }
```
