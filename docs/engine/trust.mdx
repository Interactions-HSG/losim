The measurements depend on code using the model. `System.nanoTime` reads host time,
a real file bypasses the disk model, and work sent to the common pool has no node
to charge.

<Warning>
None of these actions necessarily throws. They can produce plausible figures with
unmodeled work, so the verifier records a caveat.
</Warning>

The verifier reads the lab's compiled classes before execution. It flags affected
measurements and lets the run continue. The trace records the caveat beside the
affected result:

```text
  trust: 4 nodes report figures that do not mean what they say
    w0, w1, w2
      each reads the real clock, so its timeline is not projectable
        Peeker.java:19               System.nanoTime() in map
        Peeker.java:22               System.nanoTime() in map
    spiller
      writes to a real disk, which the disk model never sees, so its disk figure
      is a lower bound
        Scribbler.java:21            Files.writeString() in map
    Nothing was stopped: each of these is a wrong number, not a broken run.
```

## Flags instead of a gate

<Columns cols={2}>
  <Card title="A gate would have to be right about generated code" icon="robot">
    protoc's output can trigger these rules. A `*Grpc` class holds mutable
    statics, and a hard gate would have to argue with every one.
  </Card>
  <Card title="A gate teaches the wrong thing" icon="lock">
    dissaly measures rather than restricts what your code does. The useful output is a
    lower bound attached to the affected node and resource, not a verdict about the
    code.
  </Card>
</Columns>

## Walk scope

The verifier walks outward from the services each node serves and the job that
drives them, then follows everything they reference that is also on the lab's
classpath.

- The JDK is not walked.
- gRPC is not walked.
- dissaly's own packages are named explicitly and skipped. They would otherwise light
  up, since the clock reads `nanoTime` and the dispatcher parks threads.
- Generated code is recognised and skipped by protobuf's superclass and grpc-java's
  `@GrpcGenerated`, not by a guess about the name.

<Note>
An empty walk is not evidence that the code is clean. If the classpath yields nothing,
the run says so rather than reporting clean:

```text
none of the classes this simulation names are on the classpath it was given, so
nothing was read. A jar is not walked; point --cp at the directory the lab
compiles to.
```

The verifier reports the empty walk instead of treating it as clean.
</Note>

## Verification cases

<AccordionGroup>
  <Accordion title="A constant is not shared state" icon="lock" defaultOpen>
    ```java
    static final Map<String, Long> M = new HashMap<>();   // flagged: one map for eight nodes
    static final String[] WORDS = {"a", "the"};           // not flagged: a table
    ```

    The difference is that nothing is **called** to build the second. The class
    initializer is read rather than inferred from the declaration.
  </Accordion>

  <Accordion title="Said by the declarations, not the call sites" icon="file-code">
    `System::nanoTime` appears in **no instruction anywhere** — only in a bootstrap
    argument. A class that `extends Thread` starts itself through a method on
    itself.

    A verifier that reads only instructions would miss both cases.
  </Accordion>

  <Accordion title="Two nodes running the same class are both flagged" icon="clone">
    The same code makes the same figure wrong on each of them. The job is attributed
    to the node it runs on, because that is whose pool executes it and whose
    counters it lands on.
  </Accordion>
</AccordionGroup>

## Flag consequences

Each rule carries a flag, and each flag names the measured resources it makes
meaningless:

| flag | consequence | undermines |
|---|---|---|
| `timeline` | its timeline is not projectable | `makespanRefMs` |
| `memory` | its memory figure is a lower bound | `memoryMb`, `allocMb` |
| `disk` | its disk figure is a lower bound | `diskMb` |
| `wire` | its wire bytes are a lower bound | `wireMb` |
| `isolation` | its figures are not only its own | **all of them** |

`isolation` affects every column. If nodes reach into each other, attribution to
either node is not reliable.

## Above `scale: 1`

```text
  memoryMb              6.823                34.07 k  +-x1.10
      w0, w1 each read the real clock, so this is a projection of the host's time
```

<Note>
An error bar describes fit quality, not whether the measured work stayed inside the
model. The caveat therefore appears next to the projected number.
</Note>

## Deliberately unchecked

The verifier does not flag code solely for determinism. Unseeded `Random`, `Math.random` and
identity-hash iteration order are all fine, because runs are not reproducible
anyway.

Raw threads are not banned either. Real concurrency inside a node is supported.
Work outside the node's own pool is attributed to nobody, and that is what gets
said.
