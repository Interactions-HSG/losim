losim's numbers mean something only if the code stays inside the simulated world.
A handler that reads `System.nanoTime` gets the host's time rather than the
compressed clock. One that writes a real file bypasses the disk model. One that
hands its work to the common pool is charged to nobody.

<Warning>
None of those throw. Each produces a run full of plausible figures, and each figure
is wrong in a way the viewer cannot see on its own.
</Warning>

So the verifier reads the lab's compiled classes before anything runs, and flags
rather than refuses. The run still happens, and what carries a caveat says so beside
itself:

```text
  trust: 4 machines report figures that do not mean what they say
    w0, w1, w2
      each reads the real clock, so its timeline is not projectable
        Peeker.java:19               System.nanoTime() in map
        Peeker.java:22               System.nanoTime() in map
    spiller
      writes to a real disk, which the disk model never sees, so its disk figure
      is a lower bound
        Scribbler.java:21            Files.writeString() in map
    Nothing was stopped: each of these is a wrong number, not a broken run.
```

## Flagging, not a gate

<Columns cols={2}>
  <Card title="A gate would have to be right about generated code" icon="robot">
    protoc's output trips these rules freely. A `*Grpc` class holds mutable
    statics, and a hard gate would have to argue with every one.
  </Card>
  <Card title="A gate teaches the wrong thing" icon="lock">
    losim measures rather than restricts what your code does. The useful output is a
    lower bound attached to the machine and the figure it undermines, not a verdict
    about the code.
  </Card>

## The walk's scope

The verifier walks outward from the services each machine serves and the job that
drives them, then follows everything they reference that is also on the lab's
classpath.

- The JDK is not walked.
- gRPC is not walked.
- losim's own packages are named explicitly and skipped. They would otherwise light
  up, since the clock reads `nanoTime` and the dispatcher parks threads.
- Generated code is recognised and skipped by protobuf's superclass and grpc-java's
  `@GrpcGenerated`, not by a guess about the name.

<Note>
Nothing walked is not the same as nothing wrong. If the classpath yields nothing,
the run says so rather than reporting clean:

```text
none of the classes this scenario names are on the classpath it was given, so
nothing was read. A jar is not walked; point --cp at the directory the lab
compiles to.
```

Reporting that as clean would be the one failure mode this check cannot afford.
</Note>

## Three things it has to get right

<AccordionGroup>
  <Accordion title="A constant is not shared state" icon="lock" defaultOpen>
    ```java
    static final Map<String, Long> M = new HashMap<>();   // flagged: one map for eight machines
    static final String[] WORDS = {"a", "the"};           // not flagged: a table
    ```

    The difference is that nothing is called to build the second. The class
    initialiser is read, rather than the declaration guessed at.
  </Accordion>

  <Accordion title="Said by the declarations, not the call sites" icon="file-code">
    `System::nanoTime` appears in no instruction anywhere, only in a bootstrap
    argument. A class that `extends Thread` starts itself through a method on
    itself.

    A verifier reading only the instructions would call both spotless.
  </Accordion>

  <Accordion title="Two machines running the same class are both flagged" icon="clone">
    The same code makes the same figure wrong on each of them. The job is attributed
    to the machine it runs on, because that is whose pool executes it and whose
    counters it lands on.
  </Accordion>
</AccordionGroup>

## Each flag, and what it undermines

Each rule carries a flag, and each flag names the measured resources it makes
meaningless:

| flag | consequence | undermines |
|---|---|---|
| `timeline` | its timeline is not projectable | `makespanRefMs` |
| `memory` | its memory figure is a lower bound | `memoryMb`, `allocMb` |
| `disk` | its disk figure is a lower bound | `diskMb` |
| `wire` | its wire bytes are a lower bound | `wireMb` |
| `isolation` | its figures are not only its own | all of them |

`isolation` poisons everything rather than one column. If machines reach into each
other, attributing anything to either of them is arithmetic on a fiction.

## In scaled mode

```text
  memoryMb              6.823                34.07 k  +-x1.10
      w0, w1 each read the real clock, so this is a projection of the host's time
```

<Note>
An error bar says how well a law was fitted. It says nothing about whether what it
was fitted to meant anything. A machine that stepped outside the simulated world is
exactly that case, so the caveat goes next to the number.
</Note>

## Left unchecked

Nothing is flagged for determinism's sake. Unseeded `Random`, `Math.random`, and
identity-hash iteration order are all fine, because runs are not reproducible
anyway.

Raw threads are not banned either. Real concurrency inside a machine is a feature.
Work outside the machine's own pool is attributed to nobody, and that is what gets
said.
