<Note>
**A projection is printed only when its checks pass.** A plausible value is unusable
when the fitted behavior is unstable or changes across the measured range.

The engine tests each law before printing it. A failed test produces a refusal
reason in place of a projected value.
</Note>

## Test 1: Range stability

Split the ladder in half. Fit the lower and upper halves separately, then compare
their exponents.

```
diskMb  REFUSED: the ladder bends: over the lower half it grows as units^0.59 and
over the upper half as units^0.87, a difference of 0.28. The behavior changes
between small and large inputs. A threshold, a different code path, or a granularity
effect may cause the change, so extrapolation across the full range is unreliable.
R2 over the whole ladder is still 0.883, so an R2 threshold cannot distinguish this
case from a noisy straight line.
```

<Warning>
**R² cannot make this decision.** On a workload that spills above a key count, R²
over the whole ladder falls only to about **0.74**, a value that a noisy *linear*
workload can also produce.

The refusal includes R² so the result explains why R² alone was insufficient.
</Warning>

The test uses the axis on which the ladder was measured, **units**. A resource that
bends against units changes behavior between the small and large ends. Changing
the variable would hide the bend rather than make extrapolation valid.

## Test 2: Exponent reproducibility

Refit on independent seed sets with the same workload and sizes but different
random draws. The spread is the error bar.

```
makespan  REFUSED: its exponent moves by 0.66 between independent seed sets of the
same workload. At a factor of 5000, this gives an error bar of x268, wider than
anything the projection would need to distinguish.
```

R² measures fit to the observed points. It does not measure whether independent
runs produce the same exponent.

<Note>
Measured: on short handlers the **time** exponent moves by about 0.25 between
independent seed sets of an identical workload, while **memory** does not move at
all. The engine measures this per host and workload instead of assuming a constant.
</Note>

## Test order

An exponent must be reproducible before it can support the bend test. An unstable
measurement is refused **as unreproducible** and omitted from the bend test.

## Run-level refusals

These stop the run before it happens.

<AccordionGroup>
  <Accordion title="the variable part does not dominate the fixed overhead">
    ```
    memoryMb at 8000 units is only 2.4x its own fixed overhead (0.31 against 0.13);
    below 10x the fit is describing the overhead rather than the workload
    ```

    Checked only for resources the solve caps: memory and disk. A large fixed term
    elsewhere means that resource's law is weak; it does not make the run size
    invalid. Refusing the whole run would leave no runnable result.
  </Accordion>
  <Accordion title="the system would not fit this host">
    ```
    at 8000 units the system would hold 4200 MB, and this host offers 1843 MB to
    work in — the run does not fit the laptop it is meant to fit on
    ```

    The engine uses at most **60%** of the JVM's max heap.
  </Accordion>
  <Accordion title="k_time is finer than the workload can express">
    The finest fitted cost site must stay above the sleep debt's
    fifty-times-below-the-floor limit. The message computes the largest `k_time`
    that works.
    [Sleep debt ->](/engine/sleep-debt)
  </Accordion>
</AccordionGroup>

When no feasible size exists:

```
thumbs-scaled.yaml  a scale above 1: no feasible size
  <the reason>
  Because no feasible size exists, nothing runs and no projection is reported.
```

## Refusals in the bill

Capacity depends on the timeline. When the timeline is refused, the capacity line
is refused too. It quotes the engine's reason rather than paraphrasing it:

```
  capacity    the system, for the period            -           CHF   refused
      its exponent moves by 0.793 between independent seed sets of the same
      workload, which over a factor of 6 is an error bar of x4.1
```

Cross-zone egress uses the **wire** law. Which calls cross a zone depends on the
topology, so egress has no separate size law. If the wire law is refused, the
egress line is also refused and does not present an observed quantity as a
full-scale value.

## Do not bypass a refusal

<Warning>
**The thresholds are fixed.** The tests examine range stability and exponent
reproducibility.

Multiplying a small run by the size ratio ignores the rejected behavior and can
materially misestimate sublinear workloads.
</Warning>
