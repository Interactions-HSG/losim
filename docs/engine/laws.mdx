```
resource = fixed + coefficient x variable ^ beta
```

```
memoryMb = 0.0597 + 0.00187 * revealed.distinctItems^1.013  (R2 1.0000, wobble 0.000)
```

| term | |
|---|---|
| `fixed` | overhead present at every scale, such as a JVM baseline heap |
| `coefficient`, `beta` | the variable part |
| `variable` | what the resource turned out to be a function of |
| `R2` | how well the line went through the points it was given |
| `wobble` | how far the exponent moves when fitted on independent seeds |

## Candidate variables

The engine considers each quantity that **varied** across the ladder and could
explain a resource:

- `units` — what the simulation declared
- every numeric `Losim.current().reveal(key, value)` your code made

Each resource is fitted against every candidate, then the selection rules choose
one.

<Note>
`reveal("distinctItems", index.size())` lets the engine test whether memory follows
the retained vocabulary rather than the record count.
</Note>

## Composing laws

A variable that is not `units` is **itself fitted against units**:

```
memoryMb      = f(distinctItems)
distinctItems = g(units)
```

The projection composes the two laws. The resource exponent also magnifies
uncertainty in the variable, so the composed result cannot be more certain than
its input.

## Candidate selection

The engine chooses candidates in this order:

<Steps>
  <Step title="Would it be reproduced?">
    A usable candidate has an error bar within limits **and** a ladder that does not
    bend. Unusable candidates lose to usable ones outright.
  </Step>
  <Step title="Which has the narrower error bar?">
    Prefer the candidate with the narrower error bar, within a tolerance of 0.01.
  </Step>
  <Step title="A tie goes to `units`">
    `units` is known **exactly** at full scale rather than being projected.

    Another variable must reduce unexplained variance by at least half. This avoids
    selecting a variable that adds a constant offset and extrapolates it as growth.
  </Step>
  <Step title="Only then, R²">
  </Step>
</Steps>

<Warning>
R² measures the existing points. The selection also checks whether the law holds for
future input sizes.
</Warning>

## Wobble and error bars

```java
wobble  = the spread of beta across independent seed sets
errorBar = scaleFactor ^ (wobble + carried)
```

An exponent uncertainty of `wobble` becomes a factor of `F^wobble`, where `F` is the
projection factor. Over a factor of 5000, a wobble of 0.66 gives an error bar of
**x268**.

The engine refuses a projection whose error bar exceeds **x2.0**.

<Note>
Wobble is measured **per host and per workload** rather than assumed, because a
two-core Codespace is noisier than a laptop and the same constant would not serve
both.
</Note>

## One law per cost site

A hash lookup is flat in `n`; a per-unit scan is linear; a sort is `n log n`; a
fan-out is quadratic in the system. Each cost site therefore gets its own law.

The engine keeps a cost-site law only when it would **survive another measurement**.
Handlers shorter than host jitter usually fail the `k_time` feasibility check.

## Fault amplification

Each resource carries a multiplier derived from the fault column. It compares demand
under faults with demand in clean runs, applies that ratio at projection time, and
appears beside the law when it is meaningfully above 1:

```
  memoryMb   = 0.0597 + 0.00187 * revealed.distinctItems^1.013  +-x1.10  x1.97 under fault
```
