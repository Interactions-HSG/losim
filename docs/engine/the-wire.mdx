title: "The wire"
description: "The interceptors between a gRPC call site and its handler."

---

losim intercepts each call on both sides of gRPC. Calls use an in-process
transport; there is no separate transport layer or message bus.

```text
caller                                                   callee
  │
  ├─ Retrying          (only if the simulation declared a policy)
  │    └─ ClientSide   the network, byte counts, spans, deadlines
  │         │
  │         ├──── in-process transport ────────────────┐
  │                                                    │
  │                                        ServerSide ─┤  cost, context, units
  │                                                    └─ your handler
```

## Before the call

The client checks these conditions in order:

| | `why` |
|---|---|
| the target node is not alive | `unreachable` |
| the two ends cannot reach each other | `partitioned` |
| the draw against `loss` came up | `lost` |

Each condition returns a `Dropped` call. It opens a span marked
`delivered: false`, counts the attempted request bytes, waits out the caller's
deadline, and fails with `DEADLINE_EXCEEDED`.

<Note>
The caller cannot distinguish the three conditions. An immediate `UNAVAILABLE`
would model them differently from a request that waits until its deadline.

A call without a deadline waits five reference seconds, so a simulation that omits
one still terminates.
</Note>

## Client side

<Steps>
  <Step title="Rewrite the deadline into real time">
    `withDeadlineAfter(200, MILLISECONDS)` means 200 **reference** milliseconds. The
    remaining time is divided by `k_time` while the caller's intent is still
    visible.
  </Step>
  <Step title="Open a span and pass its id in metadata">
    `losim-parent-span`. The callee opens its own span under that id, so causality
    survives the boundary.
  </Step>
  <Step title="Measure the request">
    Serialized size plus five bytes of framing. Counted against the caller's
    `bytesOut`, and separately against `crossZoneBytes` if the two nodes are in
    different zones.
  </Step>
  <Step title="Measure the response too">
    Count both directions. Counting only the request would make a fetch appear
    free.
  </Step>
  <Step title="Sleep for the round trip when it closes">
    Sleep once on the thread that delivers the response. This does not change the
    callee's pool thread or the handler's measured duration.
  </Step>
  <Step title="Check the deadline again">
    Without this check, a call could succeed after the wire had already exceeded
    its deadline.
  </Step>
</Steps>

## Server side

<Steps>
  <Step title="Read the parent from the header">
    The parent arrived from another node. Reading it from the ambient context
    would attach every server span to the root.
  </Step>
  <Step title="A frozen node holds the call">
    The call waits at the door on the node's own thread. This makes a freeze
    harder to diagnose than a crash.
  </Step>
  <Step title="`handler_start` is recorded, then the fixed cost is slept">
    The order matters. Reversing it collapses the Gantt block in the trace.
  </Step>
  <Step title="Run the handler">
    The node is ambient, so `Losim.current()` works.
  </Step>
  <Step title="Sleep for the per-unit cost before sending the response">
    The handler has already reported the amount through `units(n)`.
  </Step>
  <Step title="`handler_end` is recorded, with both durations">
    `ms` is the program's duration. `grossMs` covers the interval from open to
    close, including work done by losim inside it.
  </Step>
</Steps>

## Retries sit outside the wire

The retry interceptor is installed **outside** `ClientSide`. Each attempt is a
separate call with its own span, byte count, loss draw, and check of the callee's
state.

Accounting each attempt separately keeps retries from hiding their resource cost.

## Byte counting

<Warning>
gRPC's in-process transport **does not serialize**. It passes the same object
reference to the receiver. Protobuf messages are immutable, but the transport does
not provide a byte count.

losim therefore marshals the message explicitly: `getSerializedSize()` plus 5
bytes per message, consisting of one compressed-flag byte and a four-byte length
prefix.

Anything that is not a protobuf `Message` weighs zero.
</Warning>

## Method naming

gRPC writes `lab.Thumbnailer/Thumbnail`. The trace writes
`lab.Thumbnailer.Thumbnail`, which lets downstream code split on a dot. Retry
policies match either form, a dotted suffix, or `*`.
