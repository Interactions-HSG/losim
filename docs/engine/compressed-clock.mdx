losim schedules simulated work on the host wall clock. Before sleeping, it divides
each declared duration by `k_time`.

```
what gets slept  =  refMs x (2 / vcpu) x degradeFactor / k_time
```

<Note>
`k_time` is derived from the host and the simulation scale. Authors do not set it.
It is 20x at scale 1 and rises to a ceiling of 40x.

The value is global because all nodes share one wall clock. The probe grid and the
run it fits use the same value. losim sets it before execution and checks it after
calibration.
</Note>

## Host calibration

<AccordionGroup>
  <Accordion title="parkNanos has a stable overshoot ratio" icon="chart-line" defaultOpen>
    On a reference laptop, `parkNanos` overshoots by about **1.28**. The ratio
    remains stable across three orders of magnitude, so losim measures it at
    startup for each host and corrects later sleeps.

    Calibration reduces mean error across the usable range from about **27% to
    about 3%**.

    The calibration uses the durations it will actually be applied to:
    0.05, 0.1, 0.25, 0.5, 1 and 2 ms. Below the floor the measurement's own overhead
    dominates, and including those points would let the noisiest one set the
    calibration for every other.
  </Accordion>

  <Accordion title="Below about 0.05 ms, measurement overhead dominates" icon="ruler-horizontal">
    The measurement overhead is larger than the interval. losim records such a
    cost as **owed** and settles it later.

    Timer resolution does not cap `k_time`. A sub-floor cost remains part of aggregate
    time, but individual calls cannot be observed precisely. Ordering survives while
    placement inside the debt window does not, and the trace records that limitation.
    [Sleep debt ->](/engine/sleep-debt)
  </Accordion>
</AccordionGroup>

## Clock origin

Building six in-process servers costs real milliseconds. At 20x, that setup time
would consume hundreds of reference milliseconds.

Without an offset, faults scheduled near the start could fire during setup. losim
starts the simulation clock after system construction so trace times match simulation
times.

The clock is zeroed after system construction. Setup work therefore belongs to no
simulation timestamp.

## Effects of `k_time`

| | divided by `k_time`? |
|---|---|
| `simulatedDuration:`, both terms | yes |
| `Losim.current().sleep(refMs)` | yes |
| network latency and jitter | yes |
| `withDeadlineAfter(…)` | yes |
| when a drawn failure fires | yes |
| the sampler's cadence | yes |
| **`Thread.sleep(...)`** | **no**; it is host time and is independent of compression |

The verifier flags `Thread.sleep` because it bypasses this clock.

## Compression values

| | |
|---|---|
| scale 1 | **20x**. A scale-1 run uses this value. |
| scale above 1 | **40x**, the ceiling. The probe grid uses this value for larger simulations. |

The ceiling keeps sleep debt within the timer's usable range. If a declared cost is
smaller than the clock can express, the engine reports the cost site after the grid:

```
this run is clocked at 40x real time, and lab.Thumbnailer.Capacity costs 0.0004
refMs, 6x below what the sleep debt can still settle at that compression, so its
timings would drift rather than be owed. Give that cost site more to do, or lower
the scale: at scale 1 the clock runs at 20x.
```

<Note>
The remedy is to increase the work at the cost site or use a lower scale.
</Note>

## Run variation

The run uses real threads and a real clock without a simulated scheduler. Repeating
the same simulation on one host changes durations and many byte counts.

<Note>
Use a **sweep** to measure variation across seeds. losim does not require deterministic
thread scheduling, unseeded `Random`, or identity-hash iteration order.
</Note>
