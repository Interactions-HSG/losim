There is no virtual clock. There is one real wall clock, and every declared duration
is divided by `k_time` before it is slept.

```
what gets slept  =  refMs × (2 ÷ vcpu) × degradeFactor ÷ k_time
```

<Note>
`k_time` is **declared, not chosen**. It has to be global — there is one wall clock,
and two machines sleeping under different factors would disagree about when *now* is
— and it has to be the same for the probe grid as for the run it fits, or the fit
describes a differently-compressed system.
</Note>

## Two facts about the host decide how this is built

<AccordionGroup>
  <Accordion title="parkNanos overshoots by a stable ratio, not a fixed offset" icon="chart-line" defaultOpen>
    About **1.28** on a reference laptop, and the same ratio across three orders of
    magnitude. That makes it a **calibration** problem rather than a resolution one:
    measure the ratio at startup, per host, and divide every sleep by it.

    Calibrated, mean error across the usable range falls from about **27% to about
    3%**.

    The calibration is fitted over the durations it will actually be applied to —
    0.05, 0.1, 0.25, 0.5, 1 and 2 ms. Below the floor the measurement's own overhead
    dominates, and including those points would let the noisiest one set the
    calibration for every other.
  </Accordion>

  <Accordion title="Below about 0.05 ms nothing can be expressed at all" icon="ruler-horizontal">
    The measurement's own overhead dominates the thing measured. A cost that fine is
    therefore **owed** rather than slept, and settled later.

    So `k_time` is **not** capped by timer resolution. What a sub-floor cost loses is
    per-call observability, not aggregate time: ordering survives, placement inside
    the debt window does not, and the trace has to say so.
    [The sleep debt →](/engine/the-sleep-debt)
  </Accordion>
</AccordionGroup>

## The clock starts after the fleet is built

Building six in-process servers costs real milliseconds, and at `kTime: 10` that is
hundreds of reference milliseconds of a run that has not begun.

Left alone it would put every fault written for an early instant **in the past**, so
they would all fire at once during setup — and it would mean an instant in the
scenario is not the same instant in the trace, which is the one correspondence a
reader needs.

So the clock is zeroed at `fleet.begin()`, and everything before that belongs to no
scenario.

## What `k_time` touches, and what it does not

| | divided by `k_time`? |
|---|---|
| `@Takes(refMs)` and `refNsPerRecord` | yes |
| `Losim.current().sleep(refMs)` | yes |
| network latency and jitter | yes |
| `withDeadlineAfter(…)` | yes |
| fault and chaos placement | yes |
| the sampler's cadence | yes |
| **`Thread.sleep(…)`** | **no** — the one duration in a run that does not move when the compression does |

That last row is the whole reason `Thread.sleep` is flagged.

## Choosing a value

| | |
|---|---|
| `kTime: 1` | no compression. Best for debugging: refMs are real milliseconds. |
| `kTime: 2 – 10` | a normal teaching scenario. Fast enough to iterate, slow enough that setup does not dominate. |
| `kTime: 20 – 100` | a scaled run, where the point is to fit thirty probe runs into a coffee break. |

The ceiling is set by your smallest declared cost. If you go past it, the engine says
so and computes the largest value that works:

```
k_time 400 is finer than this workload can express: lab.Thumbnailer.Capacity costs
0.5000 refMs, which at that compression is 4x below what the sleep debt can still
settle. Lower k_time to 100 or less, or give that cost site more to do.
```

## Runs are not reproducible, and that is deliberate

Real threads, a real clock, no simulated scheduler. Two runs of one scenario on one
machine differ in every duration and most byte counts.

<Note>
The answer to that is a **sweep**, not determinism. One seed shows a design survived
an afternoon; twenty show it survives afternoons. And it is why nothing is flagged
for determinism's sake — unseeded `Random` and identity-hash iteration order are
fine, because runs are not reproducible anyway.
</Note>
