## Independent axes

<Warning>
A resource that grows with the **data** can look like one that grows with the
**system** when both change together. The probe grid varies them independently so the
engine can distinguish the two effects.
</Warning>

The grid changes one axis at a time:

<Steps>
  <Step title="Data size: system and faults fixed">
    Four sizes x **six seeds**. The system is the shape declared by the simulation,
    not the largest shape in the system series. A law fitted on eight workers and
    applied to a run of two describes a different system.
  </Step>
  <Step title="System size: data and faults fixed">
    Two shapes x 2 seeds at the middle data size. Every pool with more than one node
    is regenerated at that size, keeping its instance type, zones, and services.
    **Singletons, including the coordinator, are left alone.**
  </Step>
  <Step title="Faults: data and system size fixed">
    The top data size x 2 seeds, with the simulation's own failures.
  </Step>
</Steps>

The system-size and fault series are **cross-checks**, not inputs to the error bar.
Only the data-size series uses six seeds because its exponent is tested for
reproducibility.

## Seed sets

The law is fitted on the **median of all six**. Reproducibility is measured by
refitting each independent set of two **the same way** and comparing the spread.

<Note>
Refitting on one seed would measure run noise rather than uncertainty in the
six-seed fit. Three independent sets provide the spread estimate.

Seeds are derived from the simulation's own: `seed x 1000 + i`. So a plan is
reproducible from the file.
</Note>

## Fault coverage

A killed node's work is redone elsewhere, so a surviving node absorbs its share.
This can roughly **double** peak memory on a node that accumulates the work.

A model fitted only on clean runs can under-predict by that amount. The engine records
the difference as an amplification term for each resource.

When the simulation declares no faults, the result contains a note instead:

```
note: nothing in this simulation goes wrong, so the model carries no amplification term —
      a projection from it describes a system where nothing goes wrong
```

## Minimum of four sizes

```
a ladder of 3 cannot show whether a law bends; four is the fewest that can
```

Four sizes allow the engine to compare exponents for the two halves and detect a
discontinuity. Three sizes do not provide that comparison.

## Plan cache

losim performs the probe runs once and caches the fitted plan:

```
[plan fitted from 30 probe runs in 41.2s]
[plan cached]
```

Plans are cached in `build/.losim-plans/`, keyed by **the simulation, the profiled
code, and the telemetry level**.

<Note>
The telemetry level is part of the key because the fitted law should not depend on
instrumentation. Omitting it would allow runs at different levels to reuse a plan.
</Note>

```bash
rm -rf build/.losim-plans      # force a refit
```

## Choose sizes

```yaml
scale: 5000
```

All four sizes should be in a region where the code behaves **consistently**. If it
spills, switches algorithms, or stops fitting in a cache, the engine will detect the
change and refuse the fit. Move the range to one side of that transition.

Larger sizes also help when fixed overhead dominates. The engine refuses a size where
the variable part is less than **ten times** the fixed part.
