```yaml
scale: 5000
```

`scale` is the only setting needed. At `scale: 1`, the run is measured directly.
Above 1, the engine selects and runs the probe workload before projecting the full
size.

## Running a scaled simulation

Use the same command; dissaly reads `scale` from the simulation:

```bash
java -Xmx3g -cp "${CP}build/dissaly.jar:build/dissaly/classes" \
     dissaly.cli.Main simulate thumbs-scaled.yaml \
     --cp build/dissaly/classes --out build/scaled.json
```

The first scaled run includes the fitting work:

```
thumbs-scaled.yaml  seed 5  scaled 8,000 -> 40,000,000 frames (x5,000)
                                              [plan fitted from 30 probe runs in 41.2s]
  measured at 8,000 units — what the handlers counted with units(n), and what the
  laws below are fitted in
```

dissaly runs thirty probes before the scaled run: four data sizes at six seeds, two
system shapes, and a weather column. Later runs can use the cached plan:

```
                                              [plan cached]
```

<Note>
**The plan cache** lives in `build/.dissaly-plans/` and is keyed by the simulation, the
profiled code, **and the telemetry level**. Changing any of these triggers a refit;
an unchanged configuration reuses the plan.

The telemetry level is part of the key because fitted laws must be checked against
the instrumentation level that produced them.

```bash
rm -rf build/.dissaly-plans      # force a refit
```
</Note>

## Reading the output

```
  memoryMb   = 0.0597 + 0.00187 * revealed.distinctItems^1.013  (R2 1.0000, wobble 0.000)
  wireMb     = 0.0    + 0.000151 * units^0.952                (R2 1.0000, wobble 0.004)
  diskMb       REFUSED: the ladder bends — over the lower half it grows as units^0.59
               and over the upper half as units^0.87 …
  makespan     REFUSED: its exponent moves by 0.66 between independent seed sets …

                     observed              projected
  memoryMb              6.823                34.07 k  +-x1.10
  wireMb                0.460                 2.63 k  +-x1.04
```

<AccordionGroup>
  <Accordion title="The law line" icon="function" defaultOpen>
    `resource = fixed + coefficient x variable ^ beta`

    The **fixed** term is overhead present at every scale. The **variable** term
    grows with the selected input.

    `R2` measures how well the line fits its points. `wobble` measures how far the
    exponent moves when fitted again on independent seeds; dissaly uses it to decide
    whether to keep the law.
  </Accordion>
  <Accordion title="The variable" icon="magnifying-glass">
    `revealed.distinctItems` means `reveal("distinctItems", …)` was selected as the
    independent variable instead of `units`. Peak memory can depend on retained
    items rather than processed items.

    A variable other than `units` is fitted against units first. The projection then
    composes the two fitted laws.
  </Accordion>
  <Accordion title="The error bar" icon="plus-minus">
    `+-x1.10` means the projection can vary by about 10% in either direction. It is
    `scaleFactor ^ wobble`: exponent uncertainty becomes a multiplicative factor.

    Past **x2.0**, the engine refuses the projection because its uncertainty is too
    large to support a useful distinction.
  </Accordion>
  <Accordion title="The refusals" icon="ban">
    **The ladder bends** means the resource behaves differently at small and large
    sizes, so extrapolation across the bend is invalid. A high R2 does not rule this
    out.

    **The exponent is not reproducible** means independent seed sets produce
    materially different exponents.

    [In full ->](/engine/refusals)
  </Accordion>
</AccordionGroup>

## Two bills

```bash
java -cp "$CP" dissaly.cli.Main bill build/scaled.json
```

A scaled run has two billing views: what happened and the full-size model. The
projected view multiplies fitted quantities by prices, but some quantities remain
unprojectable:

```
  capacity    the system, for the period            -           CHF   refused
      its exponent moves by 0.793 between independent seed sets of the same
      workload, which over a factor of 6 is an error bar of x4.1
```

Capacity depends on the timeline, which is often the noisiest measurement. A bill
can therefore price bytes and storage while refusing to price projected capacity.

## No feasible size

```
thumbs-scaled.yaml  a scale above 1: no feasible size
  memoryMb at 8000 units is only 2.4x its own fixed overhead (0.31 against 0.13);
  below 10x the fit is describing the overhead rather than the workload
  Nothing was run and nothing is projected. A projection that could not be made is
  absent rather than guessed.
```

Feasibility is checked in both directions: the workload must be large enough for the
variable term to dominate fixed overhead, and the scaled system must fit in the
host's heap. [Refusal handling ->](/simulate/refusals)
