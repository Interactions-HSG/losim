title: "Running one simulation"
description: "Run one simulation and interpret its report and exit code."
icon: "play"
---

```bash
CP=$(ls vendor/jars/*.jar | tr '\n' ':')

java -Xmx3g -cp "${CP}build/losim.jar:build/losim/classes" \
     losim.cli.Main simulate thumbs.yaml \
     --cp build/losim/classes \
     --out build/thumbs.json
```

## Report

```
thumbs.yaml  seed 7  completed in 2416 refMs
  1044 events, 322 spans, 68 series -> build/thumbs.json
```

Resource failures get their own line:

```
  w2 ran out of memory: 11.83 MB against a 4.0 MB cap
  w3 ran out of disk: 33.421 MB against a 32.0 MB cap
```

Verifier findings are reported separately:

```
  trust: 2 nodes report figures that do not mean what they say
    w0, w1
      each reads the real clock, so its timeline is not projectable
        Shrinker.java:41             System.nanoTime() in thumbnail
    Nothing was stopped: each of these is a wrong number, not a broken run.
```

## Order of operations

The order explains most error messages:

<Steps>
  <Step title="The simulation is parsed and checked">
    Unknown keys, unknown instance types, durations without units, and partitions
    aimed at missing nodes are rejected. **Exit code 2, nothing ran.**
  </Step>
  <Step title="The classes are read before anything runs">
    The verifier disassembles the classes named by `runs:` and walks outward from
    them. It reports caveats with source addresses.
  </Step>
  <Step title="Nodes are built and start serving">
    losim starts one in-process server and one pool per node, sized to the instance's
    vCPUs. Missing classes and no-argument constructors are discovered here.
  </Step>
  <Step title="Retry policies are checked against what the system serves">
    A policy naming an unserved method or retrying one the schema does not declare
    safe is refused **here**, before a call is made.
  </Step>
  <Step title="The clock is zeroed and the system is announced">
    Everything before this is setup and belongs to no simulation. The clock starts
    after servers are built, so setup time does not shift scheduled faults.
  </Step>
  <Step title="The sampler starts, weather is scheduled, and Job.Run is called">
    Faults use a clock that starts at zero. A fault written at 120 refMs lands at
    120 refMs in the trace.
  </Step>
  <Step title="The run ends, a final heap walk happens, the trace is written">
    A final heap walk includes a node that filled up during the final tick.
  </Step>
</Steps>

## Exit codes

| | |
|---|---|
| `0` | `Job.Run` completed |
| `1` | it did not — it threw, or it was still running after **two minutes of real time** |
| `2` | the simulation is wrong. Nothing ran. |
| `3` | something went wrong inside losim. Re-run with `LOSIM_DEBUG=1` for the stack. |

## Options

<ParamField path="--cp <paths>" type="path list">
  Colon-separated **directories** containing compiled services. Not a jar: the
  verifier reads class files from disk and does not walk into an archive.
</ParamField>
<ParamField path="--out <file>" type="path" default="build/<simulation>.json">
  Where to write the trace.
</ParamField>
<ParamField path="--seed <n>" type="long">
  Overrides the simulation's seed. Sweeps use this option to vary runs.
</ParamField>
<ParamField path="--telemetry <level>" type="FULL | NO_PAYLOAD | OFF" default="FULL">
  How much is recorded.
</ParamField>

<ParamField path="LOSIM_DEBUG" type="environment variable">
  When set, an exit-code-3 failure prints its stack trace as well as its message.
</ParamField>

## First checks

<Steps>
  <Step title="Did it complete?">
    `meta.completed` in the trace, and the exit code.
  </Step>
  <Step title="Did every node get work?">
    A node with `"calls": 0` in the `nodes` channel indicates a discovery or
    placement bug.
  </Step>
  <Step title="Did the work overlap?">
    If summed `handler` span durations exceed the wall span, work overlapped. If
    they are roughly equal, the system queued the work.
  </Step>
  <Step title="Was anything flagged?">
    The trust block. It identifies measurements that cannot support a projection.
  </Step>
</Steps>
