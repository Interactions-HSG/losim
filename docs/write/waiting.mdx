```java
Losim.current().sleep(200);      // 200 reference milliseconds
```

The value uses reference milliseconds and is divided by `k_time`. At 40x, this
waits five real milliseconds while advancing the simulated clock by 200 ms.

## Declared RPC cost

`simulatedDuration:` is fixed per RPC. Use `sleep` for a duration **known only at
runtime**, such as an attempt-dependent backoff, poll interval, or lease.

## `Thread.sleep` ignores `k_time`

`k_time` does not affect `Thread.sleep(200)`. It waits 200 wall-clock milliseconds
rather than 200 reference milliseconds, so the verifier flags it. Use
`Losim.current().sleep` instead.

## Waiting and work

<Columns cols={2}>
  <Card title="Waiting is independent of node speed" icon="gauge-simple">
    A node at half speed **computes** slower but does not **wait** longer. A
    declared wait is not multiplied by `machineFactor` or a degrade factor.

    Measured, at 40x on a node at half speed: a declared 500 takes 1019
    refMs and `sleep(500)` takes 596.
  </Card>
  <Card title="Waiting does not mark the node busy" icon="bed">
    A backoff occupies no vCPU. Counting it as occupancy would overstate system load.

    The `sleep` event places the wait on the timeline, distinguishing it from idle
    time.
  </Card>
</Columns>

## Usage patterns

<CodeGroup>
```java a growing backoff
int attempt = 0;
while (true) {
    try { return call(); }
    catch (StatusRuntimeException e) {
        if (++attempt >= 4) throw e;
        Losim.current().sleep(50 * Math.pow(2, attempt));   // 100, 200, 400 refMs
    }
}
```

```java a poll interval
while (!done()) {
    Losim.current().sleep(100);
}
```

```java a load generator
var here = Losim.current();
while (here.clockMs() < 20_000) {
    fireOneRequest();
    Losim.current().sleep(1000.0 / requestsPerSecond);
}
```
</CodeGroup>

<Tip>
Prefer the simulation's retry policy when it expresses the behavior. It is declared
data and each attempt receives its own span and byte count. Use a custom backoff when
the policy depends on program state. [Retries ->](/write/retries)
</Tip>

## Waiting on external progress

Waiting for a latch, future, `Object.wait`, or queue take is not flagged or charged.
Its duration is determined by the other operation's progress.

```java
Thumbs thumbs = future.get();        // fine: waiting for a call that is in flight
latch.await();                        // fine
Losim.current().sleep(200);           // fine: a declared wait
Thread.sleep(200);                    // flagged: your afternoon, not the run's
```

<Note>
Timeouts such as `future.get(2, SECONDS)` and `latch.await(1, SECONDS)` use real
duration and are not changed by `k_time`. If a timeout is part of the design, prefer
a gRPC deadline, which losim rewrites into reference time.
</Note>

## Outside a run

`sleep` returns immediately outside a simulation. A unit test has no compressed clock
and should not wait.
