```java
Losim.current().wroteDisk(bytes);
```

This API records the number of bytes a design would write. It does not create a
file, path, or stream; it enforces the simulated disk limit.

## Write behavior

Unlike recording calls, this operation fails when the simulated disk is full:

```java
try {
    Losim.current().wroteDisk(spill.getSerializedSize());
} catch (IllegalStateException e) {
    // w3 has no disk left: 33.4 MB written against a 32.0 MB volume
}
```

A full disk cannot accept the write, so the handler fails. Continuing after recording
the write would hide a capacity failure.

The trace records it once per node:

```json
{ "kind": "disk_full", "vm": "w3", "detail": {
    "resource": "disk", "capMb": 32.0, "demandMb": 33.421,
    "cause": "the node was asked to write more than it has" } }
```

<Warning>
**Do not write a real file.** `Files.write`, `FileOutputStream`, and
`RandomAccessFile` bypass the disk model and write to the host. The node's disk
figure then becomes a lower bound, which the verifier reports.
</Warning>

## Declaring the write

Report the number of bytes the design would write:

```java
byte[] payload = spill.toByteArray();
Losim.current().wroteDisk(payload.length);
```

or, without building the array:

```java
Losim.current().wroteDisk(spill.getSerializedSize());
```

<Note>
losim cannot independently verify the declared number. Keep it consistent when
comparing designs, as with a declared duration.
</Note>

## Reading back

There is no read API. A design that spills and re-reads pays for the spill; represent
read cost in the simulation. The disk model checks capacity and storage without
modeling a filesystem.

## Caps

The default comes from the instance type's `storageGb` and can be overridden per
node:

```yaml
nodes:
  workers:
    count: 4
    prefix: w
    instance: i3.large           # 475 GB of local storage
    runs: { Spiller: src/lab/Spiller.java }
    overrides:
      w3: { diskMb: 32 }         # deliberately too small
```

`i3.large` is the catalogue's storage-oriented instance; other types provide 8–32
GB. The selected instance family affects billing.

## Disk outputs

| where | as |
|---|---|
| series | `diskMb`, `diskPct` per node, per tick |
| `nodes` channel | `diskMb`, the closing total |
| the bill | a `GB-month` row under **consumption** |
| a scale above 1 | a `diskMb` law, fitted against whichever variable it turns out to follow |

<Tip>
Disk is often the resource whose law the engine **refuses**. A spill threshold can
make behavior differ at small and large sizes, bending the fitted range.
[Refusals ->](/engine/refusals)
</Tip>

## Observe a full disk

A volume too small for what the design writes to it:

```yaml spill.yaml
seed: 1
scale: 6

nodes:
  master:
    instance: m5.large
    zone: eu-central-1a
    runs: { losim.Job: src/lab/SpillJob.java }
  workers:
    count: 2
    prefix: w
    instance: i3.large            # the storage-shaped instance
    zone: eu-central-1a
    runs: { Spiller: src/lab/Spiller.java }
    overrides:
      w1: { diskMb: 32 }          # deliberately too small

input:
  unit:  row
  count: 60000
```

```java RunExperiments.java
Experiments.here()
        .run("spill.yaml")
        .show();
```

`w1` throws while `w0` continues, and the `disk_full` marker appears at the failure
time. In the [ledger](/viewer/views#the-ledger), the consumption bucket includes the
storage line.
