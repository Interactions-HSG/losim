```java
var here = Losim.current();
Channel to = here.channelTo(here.peersServing("Thumbnailer").get(0));
Thumbs thumbs = ThumbnailerGrpc.newBlockingStub(to).thumbnail(batch);
```

The result is an `io.grpc.Channel`. The call site remains ordinary gRPC: use the
protoc-generated stub with your request and response messages.

## Node channel

Every call through a losim channel passes through interceptors that provide:

| | |
|---|---|
| **the network** | latency by zone, jitter either side, loss, and whether the two ends can currently reach each other |
| **byte counts** | explicit message marshaling, plus gRPC's five bytes of framing |
| **cross-zone bytes** | counted separately in **both directions** |
| **spans** | one on the caller and one on the callee, with the parent sent in metadata |
| **retries** | if the simulation declared a policy for this method, outside the recording interceptor, so every attempt is genuinely separate |
| **deadlines** | rewritten from reference time into real time, so `withDeadlineAfter` means what everything else means |

## Channel ownership

```java
Channel a = here.channelTo("w1");
Channel b = here.channelTo("w1");     // the same channel
```

The node creates and keeps one channel per peer. Services on the node share it, and
the node owns its lifetime.

<Warning>
**Do not build your own.**

```java
var ch = ManagedChannelBuilder.forAddress("w1", 50051).usePlaintext().build();
```

No losim interceptor is attached. The call bypasses latency, byte counts, spans,
partitions, and node liveness checks.

The run can still produce plausible but incomplete figures. The verifier therefore
flags `ManagedChannelBuilder`.
</Warning>

## Blocking, async, and futures

<CodeGroup>
```java blocking
var stub = ThumbnailerGrpc.newBlockingStub(to)
        .withDeadlineAfter(2_000, TimeUnit.MILLISECONDS);
Thumbs thumbs = stub.thumbnail(batch);
```

```java futures — this is how you fan out
var stub = ThumbnailerGrpc.newFutureStub(to)
        .withDeadlineAfter(2_000, TimeUnit.MILLISECONDS);
ListenableFuture<Thumbs> f = stub.thumbnail(batch);
// … dispatch the rest, then collect
Thumbs thumbs = f.get();
```

```java fire and forget
ThumbnailerGrpc.newStub(to).notify(ping, new StreamObserver<Empty>() {
    @Override public void onNext(Empty v)       { }
    @Override public void onError(Throwable t)  { }
    @Override public void onCompleted()         { }
});
```
</CodeGroup>

<Note>
**Blocking in a loop serializes work.** The [Spans view](/viewer/views) shows a
staircase; concurrent work appears as overlapping blocks.

The whole round trip is slept once on the response-delivery thread. For a blocking
call this is the caller; for a future it is the channel executor. The callee's pool
thread and measured handler duration are not affected.
</Note>

## A handler can call a peer

Use the same API from a handler:

```java
@Override protected Thumbs thumbnail(Batch request) {
    if (tooBigForMe(request)) {
        var here = Losim.current();
        var bigger = here.peersServing("Thumbnailer").get(0);
        return ThumbnailerGrpc.newBlockingStub(here.channelTo(bigger)).thumbnail(request);
    }
    …
}
```

The forwarded call gets its own span under this handler's span. The handler also
occupies one core while it waits, which is part of forwarding's cost.

## Timeout details

```java
try {
    thumbs = stub.thumbnail(batch);
} catch (StatusRuntimeException e) {
    if (e.getStatus().getCode() == Status.Code.DEADLINE_EXCEEDED) {
        // dead, partitioned, or dropped — and you cannot tell which
    }
}
```

The trace records the cause even though the caller sees the same status:

```json
{ "kind": "rpc_timeout", "vm": "master",
  "detail": { "to": "w1", "method": "lab.Thumbnailer.Thumbnail",
              "status": "DEADLINE_EXCEEDED", "why": "unreachable" } }
```

`why` is `unreachable`, `partitioned` or `lost`.

<Warning>
**A call with no deadline waits five seconds and then gives up**, so the simulation
still terminates. Five seconds of *reference* time can dominate a short run. Set
deadlines explicitly.
</Warning>
