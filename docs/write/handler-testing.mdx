The adapter exposes a plain method, so test the handler as an ordinary object:

```java test/ShrinkerTest.java
import static org.junit.jupiter.api.Assertions.*;

import lab.pb.*;
import losim.api.Losim;
import org.junit.jupiter.api.Test;

class ShrinkerTest {

    @Test void makesOneThumbnailPerFrame() {
        var shrinker = new Shrinker();

        Thumbs thumbs = shrinker.thumbnail(Split.newBuilder()
                .addFrames(frame("a", 640, 480))
                .addFrames(frame("b", 800, 600))
                .build());

        assertEquals(2, thumbs.getThumbsCount());
        assertEquals(128, thumbs.getThumbs(0).getWidth());
    }

    private static Frame frame(String id, int w, int h) {
        return Frame.newBuilder().setId(id).setWidth(w).setHeight(h)
                .setPixels(com.google.protobuf.ByteString.copyFrom(new byte[w * h / 64]))
                .build();
    }
}
```

The test runs without a system, interceptor, or simulation clock.

## losim on the classpath

`Losim.current()` must resolve. Outside a run, recording calls are no-ops and state
calls fail.

<Columns cols={2}>
  <Card title="Recording calls are silent" icon="volume-xmark">
    ```java
    Losim.current().reveal("frames", 3);   // returns
    Losim.current().log("counted");        // returns
    Losim.current().units(1);            // returns
    Losim.current().wroteDisk(4096);       // returns
    Losim.current().sleep(5_000);          // returns immediately
    ```
    A handler can therefore be called without a simulation.
  </Card>
  <Card title="State calls throw" icon="triangle-exclamation">
    ```java
    Losim.current().node();        // throws
    Losim.current().here();           // throws
    Losim.current().peers();          // throws
    Losim.current().peersServing(…);  // throws
    Losim.current().clockMs();        // throws
    Losim.current().channelTo(…);     // throws
    ```
  </Card>
</Columns>

```
no simulation is running, so Losim.current().peers() has no answer here.
Recording calls (reveal, log, units) are silent outside a run; state calls are
not, because a fabricated system would make a passing test meaningless.
```

<Note>
**The asymmetry is deliberate.** A silent `reveal` supports direct handler tests;
state calls fail because no simulated system exists.

`sleep` returns immediately because a unit test has no compressed clock and should
not incur simulated waiting.
</Note>

## Testing API calls

```java
@Test void isRunningIsFalseInATest() {
    assertFalse(Losim.current().isRunning());
}

@Test void recordingDoesNotThrow() {
    assertDoesNotThrow(() -> Losim.current().reveal("frames", 3));
}

@Test void askingAboutASystemThatIsNotThereFails() {
    var e = assertThrows(IllegalStateException.class, () -> Losim.current().node());
    assertTrue(e.getMessage().contains("no simulation is running"));
}
```

If a handler needs the node's identity, guard the state call:

```java
@Override protected Thumbs thumbnail(Split request) {
    var here = Losim.current();
    if (here.isRunning()) here.reveal("on", here.node());
    return work(request);
}
```

<Tip>
Keep losim-dependent calls out of the core logic when possible. A private method that
accepts its own arguments does not need a simulation-state branch.
</Tip>

## Running the tests

JUnit is kept separate from the system classpath. The repository stores its test jars
under `vendor/test-jars/` and runs them separately:

```bash
CP=$(ls vendor/jars/*.jar | tr '\n' ':')
TCP=$(ls vendor/test-jars/*.jar | tr '\n' ':')

javac -nowarn --release 21 -cp "${CP}${TCP}build/losim.jar:build/losim/classes" \
      -d build/test-classes $(find test -name '*.java')

java -jar vendor/test-jars/junit-platform-console-standalone-*.jar execute \
     --class-path "${CP}build/losim.jar:build/losim/classes:build/test-classes" \
     --scan-class-path build/test-classes --details=tree
```

## Unit-test limits

System-level behavior requires a simulation:

| | |
|---|---|
| whether the fan-out overlapped | a run, and the span tree |
| whether a node ran out of memory | a run, with a cap |
| whether the master noticed a dead peer | a run, with a fault |
| what any of it cost | a run, and the bill |

Use **unit tests for what one handler computes and simulations for interactions
between nodes**. This keeps handler failures small and easier to diagnose.
