```yaml
retries:
  - { method: Thumbnail, attempts: 3, backoff: 50 refMs, multiplier: 2 }
```

This permits three attempts. The waits before attempts two and three are 50 refMs
and 100 refMs.

## Policy location

Retrying is an **operational** decision, so put it in the simulation where it can be
reviewed and swept. The handler remains independent of deployment policy.

## Schema validation

Whether retrying is *safe* is a property of the **method**, not deployment. It lives
in the `.proto`; losim refuses a policy that disagrees with the schema:

```
thumbs.yaml:22: retrying lab.Volley.Hit is refused — its .proto declares no
idempotency_level, so running it twice is not known to be safe. Declare
'option idempotency_level = IDEMPOTENT;' on the rpc if it is, or write
'unsafe: true' here if you mean to retry it anyway.
```

Declare it if it is true:

```proto
service Thumbnailer {
  // Reads data and does not change it.
  rpc Thumbnail (Split) returns (Thumbs) { option idempotency_level = NO_SIDE_EFFECTS; }
}

service Registry {
  // Repeating it produces the same final state as one call.
  rpc Announce (Health) returns (Empty) { option idempotency_level = IDEMPOTENT; }
}
```

Or say you mean it:

```yaml
retries:
  - { method: Append, attempts: 3, unsafe: true }
```

<Note>
`unsafe: true` makes the exception explicit in the simulation configuration.
</Note>

## Matching a method

```yaml
- { method: Thumbnail }                      # the bare rpc name
- { method: lab.Thumbnailer.Thumbnail }      # fully qualified, dotted
- { method: Thumbnailer.Thumbnail }          # a suffix of the dotted name
- { method: "*" }                            # everything the system serves
```

A policy naming a method **no node in the system serves** is also refused.

## Attempt accounting

The retry interceptor sits **outside** the recording interceptor. Each attempt gets:

- its own span and its own row in the trace,
- its own byte count, in both directions,
- its own draw against packet loss,
- its own look at whether the callee is still alive.

<Warning>
A retry that reused the first attempt's accounting would make a retrying design look
**cheaper** than one that does not. Additional attempts increase wire and capacity
costs.
</Warning>

The trace says what happened:

```json
{ "kind": "retry", "vm": "master", "detail": {
    "method": "lab.Thumbnailer.Thumbnail", "attempt": 1, "of": 3,
    "after": "DEADLINE_EXCEEDED", "backoffRefMs": 50.0 } }

{ "kind": "retry_done", "vm": "master", "detail": {
    "method": "lab.Thumbnailer.Thumbnail", "attempts": 3, "status": "OK" } }
```

`retry_done` appears only when there was more than one attempt.

## Retryable statuses

<Columns cols={2}>
  <Card title="Retried" icon="rotate">
    `UNAVAILABLE`, `DEADLINE_EXCEEDED`, `RESOURCE_EXHAUSTED`, `ABORTED`, `UNKNOWN`.

    The callee was unavailable, overloaded, or too slow.
  </Card>
  <Card title="Not retried" icon="ban">
    Everything else, including `INVALID_ARGUMENT`.

    Also calls where a message already arrived, cancelled calls, and any
    **streaming** call. Replaying a stream would require buffering it.
  </Card>
</Columns>

## Retries and deadlines

Each attempt gets the same `CallOptions`, which means the same **absolute**
deadline. A three-attempt policy with a growing backoff can exhaust the deadline
before it exhausts its attempts:

```json
{ "kind": "retry_done", "detail": { "attempts": 2, "status": "DEADLINE_EXCEEDED" } }
```

The second attempt had no time to succeed. If three attempts are required, the
deadline must cover all attempts and backoffs.

## Custom retry loops

The simulation's policy is fixed per method. Use `Losim.current().sleep(refMs)` in
your own loop when the decision depends on program state, such as which peer to try,
how many peers remain, or whether work was already redone:

```java
for (int attempt = 1; ; attempt++) {
    var workers = Losim.current().peersServing("Thumbnailer");
    if (workers.isEmpty()) throw new IllegalStateException("nobody left");
    try {
        return call(workers.get(attempt % workers.size()), split);   // a different peer
    } catch (StatusRuntimeException e) {
        if (attempt >= 3) throw e;
        Losim.current().sleep(50 * Math.pow(2, attempt));
    }
}
```

The declarative policy retries the same peer. A custom loop can choose a **different**
peer.

## Observe retries

This example makes the retry trade-off visible:

```yaml retrying.yaml
seed: 4
nodes:
  master:
    instance: m5.large
    zone: eu-central-1a
    runs: { losim.Job: src/lab/RenderJob.java }
  workers:
    count: 3
    prefix: w
    instance: c5.large
    zone: eu-central-1a
    runs: { Thumbnailer: src/lab/Shrinker.java }

network:
  loss: 0.08

retries:
  - { method: Thumbnail, attempts: 3, backoff: 40 refMs, multiplier: 2 }
```

Save a second simulation beside the first without the `retries:` block, then run both:

```java RunExperiments.java
Experiments.here()
        .run("retrying.yaml")
        .run("no-retries.yaml")
        .show();
```


Compare `retrying` with `no-retries`. The retrying run may finish when the other does
not, while its wire and capacity costs are higher.
