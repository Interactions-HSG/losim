## Service rules

<Steps>
  <Step title="Extend the ImplBase protoc generated">
    dissaly registers the class with an in-process gRPC server. The class must be a
    `BindableService`; otherwise loading is refused:

    ```
    thumbs.yaml:14: 'lab.Shrinker' is not a gRPC service. It has to extend the
    ImplBase that protoc generated — nodes talk over gRPC and nothing else.
    ```
  </Step>
  <Step title="Give it a no-argument constructor">
    dissaly builds a fresh instance when a node restarts, so it must be constructible.
    Read runtime state through `Dissaly.current()`.

    ```
    thumbs.yaml:14: 'lab.Shrinker' needs a no-argument constructor, because dissaly
    builds a fresh one when a node restarts.
    ```

    It may be `private`; dissaly calls `setAccessible`.
  </Step>
  <Step title="Turn the callback shape back into a function">
    Write one adapter per service so the handler can be called from a unit test.
  </Step>
  <Step title="Keep every dissaly type out of every signature">
    `Thumbs thumbnail(Split)` does not depend on dissaly. The handler remains an
    ordinary object.
  </Step>
</Steps>

## Service adapter

```java
public abstract class ServiceBase extends FooGrpc.FooImplBase {

    protected abstract Reply doThing(Request request);

    @Override public final void doThing(Request request, StreamObserver<Reply> out) {
        try {
            out.onNext(doThing(request));
            out.onCompleted();
        } catch (RuntimeException e) {
            out.onError(Status.INTERNAL
                    .withDescription(String.valueOf(e.getMessage()))
                    .withCause(e).asRuntimeException());
        }
    }
}
```

<Warning>
**Catch and describe.** If a `RuntimeException` escapes, the caller receives
`UNKNOWN` and the trace lacks the reason. Put the exception message on the status.
</Warning>

## Instance lifetime and restart

dissaly builds one instance per node when the node starts serving. Fields held by the
service are node data and are included in the retained-heap walk.

The declaration determines what a restart does:

| how the simulation declares it | what a restart does |
|---|---|
| `runs: { Thumbnailer: src/lab/Shrinker.java }` | dissaly builds a **fresh instance**. Whatever it was holding is gone — which is what a restart is. |

The trace says which happened:

```json
{ "kind": "restart", "vm": "w1",
  "detail": { "state": "lost",
              "note": "fresh services: whatever it was holding is gone" } }
```

After a restart, the application must decide which work to repeat.

## Multiple services on one node

```yaml
nodes:
  w0:
    instance: m5.large
    runs: { Thumbnailer: src/lab/Shrinker.java, Archive: src/lab/Archive.java }
```

Both services are registered on the same server and share its thread pool. Discovery
uses the service name declared by each `.proto`.

## Node information

```java
var spec = Dissaly.current().here();
spec.node();       // "w3"
spec.instance();      // "a1.medium"
spec.zone();          // "eu-central-1b"
spec.vcpu();          // 2
spec.memoryCapMb();   // the cap it is under on THIS run
spec.diskCapMb();
spec.cores();         // vcpu / 2.0 — how much work it can take, crudely
```

These fields are free to call. They are initialized before the node starts and are
not measured as application work.

<Note>
**Local knowledge only.** This is the current node's information, never a peer's. A
process can read its own limits and metadata without a network, but not a peer's.

The caps are the **scaled** caps: what this node is allowed on *this* run, not the
instance type's full-scale values. Comparing them supports consistent placement
across scales.

`cores()` is a simple relative capacity value, not a ranking computed by dissaly.
Use it as an input to placement decisions.
</Note>

## Asynchronous calls use the same model

```proto
service Volley {
  rpc Notify (Ping) returns (Empty) { option idempotency_level = IDEMPOTENT; }
}
```

```java
VolleyGrpc.newStub(channel).notify(ping, new StreamObserver<Empty>() {
    @Override public void onNext(Empty value) { }
    @Override public void onError(Throwable t) { }
    @Override public void onCompleted() { }
});
```

An `Empty`-returning method on an async stub does not block its caller. Costs,
failures, telemetry, and byte counts still apply.
