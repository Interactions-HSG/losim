## The four rules

<Steps>
  <Step title="Extend the ImplBase protoc generated">
    losim registers your class with an in-process gRPC server. If it is not a
    `BindableService`, the scenario is refused at load:

    ```
    thumbs.yaml:14: 'lab.Shrinker' is not a gRPC service. It has to extend the
    ImplBase that protoc generated — machines talk over gRPC and nothing else.
    ```
  </Step>
  <Step title="Give it a no-argument constructor">
    losim builds a fresh instance when a machine restarts, so it must be able to
    construct one. Whatever your service needs, it asks `Losim.current()` for.

    ```
    thumbs.yaml:14: 'lab.Shrinker' needs a no-argument constructor, because losim
    builds a fresh one when a machine restarts.
    ```

    It may be `private`; losim calls `setAccessible`.
  </Step>
  <Step title="Turn the callback shape back into a function">
    Write the adapter once per service. It is the difference between a handler you
    can call from a plain unit test and one you cannot.
  </Step>
  <Step title="Keep every losim type out of every signature">
    `Thumbs thumbnail(Batch)` mentions nothing of losim's. That is what makes the
    handler an ordinary object.
  </Step>
</Steps>

## The adapter, in general

```java
public abstract class ServiceBase extends FooGrpc.FooImplBase {

    protected abstract Reply doThing(Request request);

    @Override public final void doThing(Request request, StreamObserver<Reply> out) {
        try {
            out.onNext(doThing(request));
            out.onCompleted();
        } catch (RuntimeException e) {
            out.onError(Status.INTERNAL
                    .withDescription(String.valueOf(e.getMessage()))
                    .withCause(e).asRuntimeException());
        }
    }
}
```

<Warning>
**Catch and describe.** Letting a `RuntimeException` escape gives the caller a bare
`UNKNOWN` with no description, and the trace a blank row where the one call worth
looking at should be. A call that failed has no result, so it has to carry *why*
instead — and that only happens if you put the message on the status.
</Warning>

## Where the instance lives, and what a restart does to it

One instance per machine, built when the machine starts serving. Whatever your
service holds in fields is that machine's data, and it is exactly what the
retained-heap walk measures.

That has one consequence worth planning for:

| how the scenario declares it | what a restart does |
|---|---|
| `runs: [lab.Shrinker]` | losim builds a **fresh instance**. Whatever it was holding is gone — which is what a restart is. |

The trace says which happened:

```json
{ "kind": "restart", "vm": "w1",
  "detail": { "state": "lost",
              "note": "fresh services: whatever it was holding is gone" } }
```

That is what makes "who redoes the work" a real question rather than a formality.

## Several services on one machine

```yaml
machines:
  w0:
    instance: m5.large
    runs: [lab.Shrinker, lab.Archive]
```

Both are registered on the same server, share the same thread pool, and are found
independently by whichever service name each `.proto` declares.

## What a machine may know about itself

```java
var spec = Losim.current().here();
spec.machine();       // "w3"
spec.instance();      // "t3.small"
spec.zone();          // "eu-central-1b"
spec.vcpu();          // 2
spec.memoryCapMb();   // the cap it is under on THIS run
spec.diskCapMb();
spec.cores();         // vcpu / 2.0 — how much work it can take, crudely
```

Free to call: every field is final on the machine and the record is built once,
before it boots. Nothing here is measured.

<Note>
**Local knowledge only.** This machine's, never a peer's. A real process can read
its own cgroup ceiling and its own instance metadata without a network, and cannot
read anyone else's at all.

The caps are the **scaled** caps: what this machine is allowed on *this* run, not
what the instance type says at full scale. So a job that places work by comparing
them places it the same way at either scale, which is the property the whole scale
model exists to preserve.

`cores()` is deliberately crude and deliberately not a score losim computes for
you. Placing work well is the exercise; a ready-made ranking is the exercise
already done. It is the obvious first thing to try, which is what makes it a useful
thing to beat.
</Note>

## Fire-and-forget is not a second path

```proto
service Volley {
  rpc Notify (Ping) returns (Empty) { option idempotency_level = IDEMPOTENT; }
}
```

```java
VolleyGrpc.newStub(channel).notify(ping, new StreamObserver<Empty>() {
    @Override public void onNext(Empty value) { }
    @Override public void onError(Throwable t) { }
    @Override public void onCompleted() { }
});
```

An `Empty`-returning method on an async stub does not block its caller — and costs,
faults, telemetry and byte counts apply to it exactly as to anything else. There is
no messaging path that escapes the model, because there is no second messaging path.
