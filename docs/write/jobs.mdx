```java
public final class MyJob extends JobGrpc.JobImplBase {
    @Override public void load(Input in, StreamObserver<Workload> out) { … }
    @Override public void run(Workload work, StreamObserver<Result> out) { … }
}
```

This is an ordinary gRPC service implementing losim's schema. [`losim.Job`](/ref/losim-proto)
defines both methods.

Returning from `Run` ends the simulation. Throwing also ends it, with the failure
recorded in the trace.

## Job placement

```yaml
nodes:
  master:
    instance: m5.large
    runs: { losim.Job: src/lab/MyJob.java }
```

**A single node** must run `losim.Job`, using the same `runs:` key as other services.
`Run` behaves like any handler: it occupies a pool thread, queues behind other work,
and its allocations are charged.

## RPC methods

<Columns cols={2}>
  <Card title="Load: outside the clock" icon="inbox">
    ```java
    @Override public void load(Input in, StreamObserver<Workload> out) {
        var album = Albums.of(in.getCount(), Losim.current().seed());
        out.onNext(Workload.newBuilder()
                .setCount(album.getFrameCount())
                .setType(Album.getDescriptor().getFullName())
                .setPayload(album.toByteString())
                .build());
        out.onCompleted();
    }
    ```
    The clock, sampler, span, and events are disabled, and every node ledger resets
    afterwards. Reading input is setup, not measured design work.
  </Card>
  <Card title="Run: the simulation" icon="play">
    ```java
    @Override public void run(Workload work, StreamObserver<Result> out) {
        var album = Album.parseFrom(work.getPayload());
        …
        out.onNext(Result.newBuilder().putAnswer("thumbnails", "4000").build());
        out.onCompleted();
    }
    ```
    Everything is measured. Its handler span is the trace root.
  </Card>
</Columns>

<Warning>
**`Run` receives no `Input` object.** It receives a count and bytes. The signature
also hides `input:`, `source:`, and the scale rung, enforcing the same behavior at
every rung.
</Warning>

## `Losim.current()` API

<AccordionGroup>
  <Accordion title="peers() and peersServing(service)" icon="magnifying-glass">
    Every other node by name and the live nodes serving a named service.
    [Finding peers ->](/write/finding-peers)
  </Accordion>
  <Accordion title="channelTo(node)" icon="plug">
    A channel with losim's interceptors attached. Build the generated stub on top.
  </Accordion>
  <Accordion title="seed()" icon="dice">
    The simulation's seed. A generated workload should use it so seed sweeps vary
    the workload.

    **Work size comes from `Input.count`.** The value is already shrunk to this run's
    size. [input ->](/ref/input)
  </Accordion>
  <Accordion title="local()" icon="box-archive">
    A `ConcurrentMap` owned by this node, shared by every service on it, reachable
    from no other, and emptied by a restart. Free in time, charged in memory.
  </Accordion>
  <Accordion title="clockMs() controls run-relative time" icon="clock">
    Simulated milliseconds since the run began.

    A load generator or poller that runs until the simulation ends can use this value
    to set its own duration. The simulation cannot set that duration for the program,
    because the run measures how long the work takes.

    ```java
    var here = Losim.current();
    while (here.clockMs() < 20_000) {
        fireOneRequest();
        here.sleep(50);
    }
    ```
  </Accordion>
  <Accordion title="reveal(key, value) and log(message)" icon="comment">
    A named value and a message, both recorded inside the calling span.
    [Telemetry ->](/write/telemetry)
  </Accordion>
  <Accordion title="Node-local API limits" icon="ban">
    The API cannot access another node's memory, start unaccounted threads, or query
    a peer's authoritative liveness.
  </Accordion>
</AccordionGroup>

## Naming work

There is no `phase` or `compute` field. `Run` already has a handler span.

`Run` is a handler with the root span and a core while it works. Local work is
therefore already represented. A master folding replies appears active inside
its root span.

To give a stretch of work its own name, make it an RPC on the node that should do it:

```java
var stub = FolderGrpc.newBlockingStub(here.channelTo(worker));
var answer = stub.fold(replies);
```

An RPC is appropriate when a unit of work needs its own name, placement, cost, retry
policy, or failure behavior.

For a value, use `reveal`. It costs nothing and lands in the root span:

```java
here.reveal("splits", inflight.size());
```

## Structured results

```java
out.onNext(Result.newBuilder()
        .putAnswer("thumbnails", "4000")
        .putAnswer("framesIn", "4000")
        .putAnswer("batchesLost", "0")
        .build());
out.onCompleted();
```

The result is recorded structurally, so later runs can be compared without parsing
prose. It becomes a `done` event with a rendered value:

```bash
python3 -c "
import json; t = json.load(open('build/thumbs.json'))
print([e['detail']['value'] for e in t['events'] if e['kind'] == 'done'])
"
```

## Run timeout

If `Run` has not returned after **two minutes of real time**, losim cancels it:

```
thumbs.yaml  seed 7  did not complete in 61042 refMs
  losim.Job/Run was still running after 120 seconds of real time, so the run was
  cancelled as stuck
```

The handler span closes as `CANCELLED` and a `failed` event records the reason. The
backstop uses real time so a stopped simulated clock cannot prevent termination.

## Failure of the job node

```yaml
master:
  runs: { losim.Job: src/lab/MyJob.java }
  failures:
    - { kill: true, at: 400 refMs }
```

The node loads, runs, and **ends the simulation there**. Shutting it down cancels
calls in flight, including `Run`, and the trace records the reason.

Running the job as an ordinary service means stopping its node cancels work in
progress.
