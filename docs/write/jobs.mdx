```java
public final class MyJob extends JobGrpc.JobImplBase {
    @Override public void load(Input in, StreamObserver<Workload> out) { … }
    @Override public void run(Workload work, StreamObserver<Result> out) { … }
}
```

An ordinary gRPC service, implementing a schema losim ships rather than one you
wrote. [`losim.Job`](/ref/losim-proto) has the whole of it.

`Run` returning ends the simulation. Throwing ends it too, and the trace says which
and why — a run that failed is a result, not an absence of one.

## Where it runs

```yaml
nodes:
  coordinator:
    instance: m5.large
    runs: { losim.Job: src/lab/MyJob.java }
```

**Exactly one node**, named by the same `runs:` key everything else uses. Zero is
refused; two is refused naming the second. It is an ordinary node otherwise: `Run`
occupies one of its pool threads, queues behind its other work, and is charged for
what it allocates. Give it headroom.

## Two rpcs, and the line between them

<Columns cols={2}>
  <Card title="Load — off the clock" icon="inbox">
    ```java
    @Override public void load(Input in, StreamObserver<Workload> out) {
        var album = Albums.of(in.getCount(), Losim.current().seed());
        out.onNext(Workload.newBuilder()
                .setCount(album.getFrameCount())
                .setType(Album.getDescriptor().getFullName())
                .setPayload(album.toByteString())
                .build());
        out.onCompleted();
    }
    ```
    No clock, no sampler, no span, no events — and every node's ledger is reset
    afterwards. Reading a file is not part of the design being measured.
  </Card>
  <Card title="Run — the simulation" icon="play">
    ```java
    @Override public void run(Workload work, StreamObserver<Result> out) {
        var album = Album.parseFrom(work.getPayload());
        …
        out.onNext(Result.newBuilder().putAnswer("thumbnails", "4000").build());
        out.onCompleted();
    }
    ```
    Everything measured. Its handler span is the trace's root, and everything else
    nests beneath it.
  </Card>
</Columns>

<Warning>
**`Run` never sees `Input`.** It gets a count and some bytes. It cannot read
`input:`, cannot see the `source:`, and cannot tell which rung of a ladder it is on
— which is the property every projection depends on, stated in the signature rather
than asked for here.
</Warning>

## `Losim.current()`'s surface, and its limits

<AccordionGroup>
  <Accordion title="peers() and peersServing(service)" icon="magnifying-glass">
    Every other node by name; and the nodes serving a named service, live ones
    only. [Finding peers ->](/write/finding-peers)
  </Accordion>
  <Accordion title="channelTo(node)" icon="plug">
    A channel with losim on it. Build whatever stub your `.proto` generated on top.
  </Accordion>
  <Accordion title="seed()" icon="dice">
    The simulation's seed. A `Load` that generates its own workload needs one, and
    it has to come from here: a workload that draws from a constant of its own is a
    workload whose every run is the same afternoon.

    **How much work there is does not come from here.** It comes in `Input.count`,
    already shrunk to this run's size. [input ->](/ref/input)
  </Accordion>
  <Accordion title="local()" icon="box-archive">
    A `ConcurrentMap` owned by this node, shared by every service on it, reachable
    from no other, and emptied by a restart. Free in time, charged in memory.
  </Accordion>
  <Accordion title="clockMs()" icon="clock">
    Simulated milliseconds since the run began.

    A design whose shape is *keep going until the run is over* — a load generator, a
    poller — rather than *do this much work* names its own stretch against it. The
    simulation cannot name one for you: how long a run takes is what the run is for.

    ```java
    var here = Losim.current();
    while (here.clockMs() < 20_000) {
        fireOneRequest();
        here.sleep(50);
    }
    ```
  </Accordion>
  <Accordion title="reveal(key, value) and log(message)" icon="comment">
    A named value and a line of narration, both landing inside the span they were
    called from. [Telemetry ->](/write/telemetry)
  </Accordion>
  <Accordion title="Its limits" icon="ban">
    It cannot reach into another node's memory, start a thread nothing accounts
    for, or ask whether a peer is alive. The last one because no real network
    offers it, and a design that depends on knowing is a design that will not
    survive contact with one.
  </Accordion>
</AccordionGroup>

## Naming a stretch of work

There is no `phase` and no `compute`. Both existed because the job was a Java object
running outside any call, with no span of its own and nothing to nest under.

`Run` is a handler. It has a span — the root — and it occupies a core while it
works, so local work is already covered and already counted. A coordinator that
spends four hundred milliseconds folding replies is not idle in the trace: it is
inside its own root span, with the node's occupancy showing it.

What is gone is the ability to give that stretch a *name of its own* without moving
it. If a stretch is worth naming, make it an rpc on the node that should be doing
it:

```java
var stub = FolderGrpc.newBlockingStub(here.channelTo(worker));
var answer = stub.fold(replies);
```

Which is not a workaround. A stretch of work worth naming is a stretch worth being
able to move, price separately, retry, or watch fail — and all four of those need it
to be an rpc anyway.

For a value rather than an interval, `reveal` costs nothing and lands in the root
span:

```java
here.reveal("batches", inflight.size());
```

## The answer, and why it is not a `log`

```java
out.onNext(Result.newBuilder()
        .putAnswer("thumbnails", "4000")
        .putAnswer("framesIn", "4000")
        .putAnswer("batchesLost", "0")
        .build());
out.onCompleted();
```

Recorded structurally, so a later run can be compared to this one without parsing
English. It lands as a `done` event with a rendered value, which is what a
regression check reads:

```bash
python3 -c "
import json; t = json.load(open('build/thumbs.json'))
print([e['detail']['value'] for e in t['events'] if e['kind'] == 'done'])
"
```

## A job that outstays its welcome

If `Run` has not returned after **two minutes of real time**, losim cancels the call:

```
thumbs.yaml  seed 7  did not complete in 61042 refMs
  losim.Job/Run was still running after 120 seconds of real time, which is not a slow
  run — it is a stuck one
```

The handler span closes `CANCELLED` and a `failed` event says why, rather than a
span that never ends. That is a backstop, not a deadline, and it is in real time on
purpose: it is the one clock still worth trusting when the simulated one has stopped
advancing.

## Killing the node it runs on

```yaml
coordinator:
  runs: { losim.Job: src/lab/MyJob.java }
  failures:
    - { kill: true, at: 400 refMs }
```

Loads, runs, and **ends the simulation there**. Shutting a node down cancels the
calls in flight on it, and `Run` is one of them. The trace says so rather than
reporting a bare `CANCELLED`.

That is not a bug to route around. It is what it costs for the thing that starts the
work to be an ordinary service, and it is worth doing once deliberately to see it.
