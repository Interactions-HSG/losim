## From a handler or job

<CodeGroup>
```java inside a handler
var here = Losim.current();
List<String> workers = here.peersServing("Thumbnailer");   // never includes itself
List<String> everyone = here.peers();                      // every other node
```

```java inside Job.Run
var here = Losim.current();
List<String> workers = here.peersServing("Thumbnailer");   // never includes itself
List<String> everyone = here.peers();
```
</CodeGroup>

<Warning>
`peersServing` excludes **this** node. A blocking self-call would occupy one pool
thread while waiting for another thread on the same node.

`Job.Run` is a handler like any other, so the same rule applies. The node running
`losim.Job` is usually the master and serves no other service.
</Warning>

## Use the `.proto` service name

```proto
package lab;
service Thumbnailer { … }
```

```java
here.peersServing("Thumbnailer");        // works — the bare name
here.peersServing("lab.Thumbnailer");    // works — the fully qualified name
here.peersServing("Shrinker");           // finds nothing: that is your Java class
```

Both forms are registered. Use the same service string as the `runs:` **key**:

```yaml
runs: { lab.Thumbnailer: src/lab/Shrinker.java }
```

The key is the service and the value is the file. losim refuses a mismatch between
the key and the class's implemented service.

## Peer discovery and liveness

```java
here.peersServing("Thumbnailer")   // ["w0", "w2", "w3"] — w1 was killed
```

<Note>
That is **discovery**, not a health API. losim does not provide an authoritative
`isAlive` query because a network cannot guarantee one.

A stopped node is detected when a call fails or reaches its deadline. It can leave
between discovery and dispatch.
</Note>

The distinction has a practical consequence. Compare:

<CodeGroup>
```java asks once
var workers = here.peersServing("Thumbnailer");     // before the loop
for (var batch : batches)
    dispatch(workers.get(i++ % workers.size()), batch);
```

```java asks again
for (var batch : batches) {
    var workers = here.peersServing("Thumbnailer"); // each time round
    if (workers.isEmpty()) throw new IllegalStateException("nobody left");
    dispatch(workers.get(i++ % workers.size()), batch);
}
```
</CodeGroup>

The first keeps sending work to a node after it dies and pays a deadline for each
batch. The second refreshes discovery for each batch and can stop sooner.

## Registration

Discovery tells you which service a node serves, not its capacity, zone, or current
load.

A resource manager can collect that information through a registration call:

```proto
service Registry {
  rpc Announce (Health) returns (Empty) { option idempotency_level = IDEMPOTENT; }
}
```

```java
// On a worker, the first time it is asked to do anything:
if (announced.compareAndSet(false, true)) {
    var spec = Losim.current().here();
    var desk = Losim.current().peersServing("Registry").get(0);
    RegistryGrpc.newBlockingStub(Losim.current().channelTo(desk))
        .announce(Health.newBuilder()
            .setMachine(spec.node()).setVcpu(spec.vcpu())
            .setMemoryCapMb(spec.memoryCapMb()).build());
}
```

The table can become stale, so placement must account for its age.

## Zones

```java
Losim.current().here().zone()      // "eu-central-1b"
```

Only your own zone is available locally; a peer can report its zone. Traffic
**between** availability zones is billed, traffic within one is free, and cross-zone
latency is typically five to ten times same-zone latency.
