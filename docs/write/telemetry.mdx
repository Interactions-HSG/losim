Telemetry provides evidence for inspecting multi-node behavior without changing the
measured result.

The API provides calls for different kinds of information.

## `reveal(key, value)`

```java
Losim.current().reveal("frames", request.getFramesCount());
Losim.current().reveal("jpegKb", bytes / 1024.0);
Losim.current().reveal("cacheHit", hit);
Losim.current().reveal("strategy", "forwarded");
```

Without it, the trace records that a handler ran. With it, the trace records selected
values from the computation.

Lands as a `state` event on the node, inside the handler's span:

```json
{ "t": 71.2, "kind": "state", "vm": "w0",
  "detail": { "key": "frames", "value": 25 } }
```

<Warning>
**Use the primitive overloads.** They cover `int`, `long`, `double`, `boolean`, and
`String`; `Object` is the fallback.

`reveal(String, Object)` boxes an `int` at the **call site**, before losim's
accounting starts, so that allocation is charged to the program. Use a primitive
overload to keep the boxing inside losim's accounting.
</Warning>

## `units(n)`: Independent variable

```java
Losim.current().units(request.getFramesCount());
```

The simulation charges `perUnit:` against it; without it, only the fixed part is
slept. The scale engine also uses it as the independent variable for a cost site.

## `log(message)`: Text

```java
Losim.current().log("forwarding to a node with more memory");
here.log(workers.size() + " nodes can make thumbnails");
```

Use `log` for text that is not a key-value value. Use `reveal` for values that later
runs should compare.

## Automatic measurements

losim records these automatically:

  <Card title="Every call, both ends" icon="right-left">

It also records faults, retries, queue waits, out-of-memory events, timeouts, and node
startup.

## Telemetry levels

```bash
--telemetry FULL        # default: everything, including payloads
--telemetry NO_PAYLOAD  # events, spans and series, but nothing rendered
--telemetry OFF         # nothing
```

Payload rendering is the most expensive part. Use `FULL` for inspection and
`NO_PAYLOAD` for measurement runs.

<Note>
Recording runs on node threads, so losim meters **its own work** and subtracts it from
the application counters. The `nodes` channel publishes the correction as `losimMb`
and `losimStops`.

The correction keeps fitted laws independent of the amount of instrumentation.
[How that works ->](/engine/self-accounting)
</Note>

## Payload limits

Payloads are bounded before they are embedded in a trace:

| | |
|---|---|
| collections | first **12** entries, then a `"+1106 more"` marker |
| strings | first **120** characters, then `"… (4021 chars)"` |
| nesting | four levels, then `"…"` |
| map fields | sorted by key, so two runs are comparable |
| default values | omitted — a zero, an empty string and a `false` are not recorded |

<Warning>
The real count is **kept plus marker**, not the number of displayed entries. A split
of 25 frames renders as 12 frames and a marker.
</Warning>

## Reading the trace

The trace is JSON and can be asserted on directly, as in the reference suite:

```python
import json
t = json.load(open("build/thumbs.json"))

frames = sum(e["detail"]["value"] for e in t["events"]
             if e["kind"] == "state" and e["detail"]["key"] == "frames")
assert frames == 4000, f"lost some frames: {frames}"

lost = [e for e in t["events"] if e["kind"] == "rpc_timeout"]
print(len(lost), "calls did not answer in time")
```
