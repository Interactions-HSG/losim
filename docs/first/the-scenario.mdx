Create `thumbs.yaml`:

```yaml thumbs.yaml
seed: 7
kTime: 4
job: lab.ThumbnailJob
expectedRun: 6 refSeconds

workload:
  records: 4000                # frames in the album

machines:
  coordinator:
    instance: m5.large
    zone: eu-central-1a

  workers:
    count: 4
    prefix: w
    instance: c5.large
    zone: [eu-central-1a, eu-central-1b]
    runs: [lab.Shrinker]
    overrides:
      w3: { instance: a1.medium }    # one core against their two, and it will show

network:
  sameZone:  0.4 refMs
  crossZone: 3 refMs
  jitter:    0.5 refMs
```

That is a complete scenario. Run it as it stands and everything works; the next
page does exactly that, and the page after adds the weather.

## Line by line

<ParamField path="seed" type="long" default="1">
  Everything random in the run is drawn from this: which machine chaos picks, how
  jitter falls, and — through `cluster.seed()` — your own workload. **One seed
  shows a design survived an afternoon; twenty show it survives afternoons.**
</ParamField>

<ParamField path="kTime" type="double" default="1">
  How much faster than reality the run goes. At `4`, a declared 800 refMs takes
  200 real milliseconds. Higher compresses more; the ceiling is set by how fine
  your smallest declared cost is. [The compressed clock →](/engine/compressed-clock)
</ParamField>

<ParamField path="job" type="class name" required>
  Fully qualified. It must implement `losim.api.Job` and have a no-argument
  constructor. It runs on the **first machine in the file** — here, the
  coordinator — so its calls and its memory are attributed to that machine.
</ParamField>

<ParamField path="expectedRun" type="duration" default="10 refSeconds">
  A **horizon, not a prediction**. Two things have to be sized before a run
  starts: how often to sample, so the trace's size follows duration rather than
  busyness, and how far ahead to draw the weather.

  If the run overruns it by more than a quarter, the trace gets an `over_horizon`
  event saying so — because past the horizon the sampler thins out and chaos stops
  firing, and a quiet second half looks exactly like a fleet behaving well.
</ParamField>

<ParamField path="workload.records" type="long">
  How much work there is. Your job reads it as `cluster.records()`.
</ParamField>

<ParamField path="machines" type="map of pools" required>
  Each key is either **one machine** (no `count:`) or a **pool** (`count: n`,
  named `prefix0 … prefix{n-1}`). Every pool member gets the same instance type,
  services and caps unless `overrides:` says otherwise, and zones are dealt round
  robin from the list.
</ParamField>

<ParamField path="machines.*.runs" type="list of class names">
  **Class names, not service names.** losim builds one instance per machine by
  reflection, so each class needs a public no-argument constructor and must extend
  the `ImplBase` protoc generated.

  A machine with no `runs` still exists and still listens — it just offers
  nothing. That is what the coordinator is.
</ParamField>

<ParamField path="network" type="object">
  `sameZone` and `crossZone` are one-way latencies; losim charges the round trip.
  `jitter` spreads uniformly either side. `loss` is a probability from 0 to 1.
</ParamField>

## Two namespaces, and mixing them up is the first mistake

<Warning>
| where | what it names | example |
|---|---|---|
| `runs:` in the scenario | your **Java class** | `lab.Shrinker` |
| `peersServing(…)` / `cluster.serving(…)` | the **service in your `.proto`** | `Thumbnailer` |

They are different strings and both are correct. The scenario has to name a class
because losim constructs it; your job has to name a service because that is what
peers are found by, and a machine can serve several classes offering one service.
</Warning>

## Every duration says what kind of time it is

```yaml
expectedRun: 6 refSeconds       # ok
crossZone:   3 refMs            # ok
crossZone:   3                  # refused
crossZone:   3ms                # refused
```

```
thumbs.yaml:18: '3ms' does not say what kind of time it is. Durations are
reference-machine time: write '3 refMs' or '3 refSeconds'. A bare number would be
ambiguous between the simulated world and your afternoon, and those differ by
k_time.
```

Accepted spellings: `refMs`, `refms`, `refSeconds`, `refSec`, `refS`, `refs`.

## Everything else that can be wrong is refused the same way

At load, with the line it was written on, before anything runs:

<CodeGroup>
```text an unknown key
thumbs.yaml:12: unknown key 'zones'; expected one of instance, zone, runs,
count, prefix, memoryMb, diskMb, overrides
```

```text an unknown instance
thumbs.yaml:9: unknown instance type 'c5.medium'; known types: a1.nano,
a1.medium, m5.large, m5.xlarge, m5.2xlarge, c5.large, c5.xlarge, …
```

```text a fault aimed at nothing
thumbs.yaml:24: there is no machine called 'w7' in this scenario;
it has coordinator, w0, w1, w2, w3
```

```text a class that is not there
thumbs.yaml:14: no class called 'lab.Shrinkr' is on the classpath. 'runs:'
names a class implementing a generated gRPC service; write it fully qualified
if it is in a package.
```
</CodeGroup>

None of those should be discovered halfway through a run as a puzzling number.
