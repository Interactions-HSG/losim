## Run a simulation

At the root of the project is an ordinary Java file with an ordinary `main`, and
your editor provides a run button above it:

```java RunExperiments.java
import dissaly.cli.Experiments;

public final class RunExperiments {

    public static void main(String[] args) throws Exception {
        Experiments.here()
                .run("main.yaml")
                .show();
    }
}
```

Each `run` reads the schema, compiles the Java, runs the system, and prices the
result. `show` opens the viewer and keeps it open.

<Note>
Edit this file to choose the simulations to run. Two `run` lines put two results
side by side in the picker:

```java
Experiments.here()
        .run("main.yaml")
        .run("slow.yaml")               // the same code, a worse afternoon
        .show();
```

A failed run is reported and the remaining runs continue. A failed simulation is
still a result for comparison.
</Note>

<Tip>
`show()` keeps the viewer open. Stop it with the stop button in your editor.

`done()` writes the traces without opening the viewer. `runAll()` runs every
simulation in the project in sequence.
</Tip>

## Build and run

For each system, dissaly runs `protoc` with the gRPC plugin, compiles with `javac`,
runs the system in its own JVM, and writes the bill.

Generated code lands in `<system>/gen/`, where the editor can resolve it. The
directory is gitignored and should not be edited.

<Warning>
Each run uses a separate JVM. A system that exhausts its heap cannot affect the
tooling or another run.
</Warning>

<Accordion title="The two classpaths, if you ever do drive it by hand">
`-cp` is what the **JVM** loads: dissaly, the vendored gRPC, and your classes.
`--cp` is where **dissaly** looks for the classes named by the simulation's `runs:` paths
resolve to, and it is also what the trust verifier reads class files from.

Point `--cp` at a **directory**. A jar is not walked, and the run will tell you so:
*"none of the classes this simulation names are on the classpath it was given, so
nothing was read."*
</Accordion>


## Output

```
thumbs.yaml  seed 7  completed in 2416 refMs
  1044 events, 322 spans, 68 series -> build/thumbs.json
```

If something went wrong you get a second line naming it, and a non-zero exit code:

```
thumbs.yaml  seed 7  did not complete in 6104 refMs
  IllegalStateException: nobody serves Thumbnailer
```

## Options

<ParamField path="--cp <paths>" type="path list">
  Where your services are compiled to. Colon-separated, directories.
</ParamField>

<ParamField path="--out <file>" type="path" default="build/<simulation>.json">
  Where to write the trace.
</ParamField>

<ParamField path="--seed <n>" type="long">
Overrides the simulation's seed for one run. A sweep loops over
`simulation.withSeed(n)` without writing intermediate files.
  [Sweeps ->](/simulate/sweeps)

</ParamField>

<ParamField path="--telemetry <level>" type="FULL | NO_PAYLOAD | OFF" default="FULL">
  How much is recorded. `FULL` includes every call's argument and result and has
  the highest overhead. `NO_PAYLOAD` keeps events, spans, and series but
  renders nothing. `OFF` keeps nothing.

  Recording runs on the nodes' own threads, so its cost appears in the measured
  counters. [What dissaly charges itself ->](/engine/self-accounting)
</ParamField>

## Exit codes

| | |
|---|---|
| `0` | `Job.Run` completed |
| `1` | it did not: it threw, or it was still running after two minutes of real time |
| `2` | the simulation is invalid; nothing ran |
| `3` | something went wrong inside dissaly |

<Note>
A failed run still produces a **result**. The trace contains
`meta.completed: false` and `meta.failure`. A simulation that kills the node the
master is waiting on produces an incomplete run with that failure recorded.
</Note>
