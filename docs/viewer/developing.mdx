<Note>
**Students use the committed page.** It is built in advance, so
[opening a trace](/viewer/opening-a-trace) only requires a static server. This page
is for viewer development.
</Note>

## Development loop

```bash
cd viewer && npm install && cd ..    # once

bin/losim dev viewer dev      # the Next dev server on :8000, with hot reload
bin/losim dev viewer check    # everything a node can decide
bin/losim dev viewer build    # the static export into viewer/out
```

`build` produces the committed export:

```bash
npx next build
```

Next writes `viewer/out`. `dev viewer serve`, the devcontainer, and `losim serve` read
that directory directly.

<Note>
**The export contains the application code.** The index remains empty until the
serving sweep adds traces.
</Note>


<Warning>
**Commit `viewer/out` with your change.** Students should not need npm or a first-run
download. A source change without the updated export is not available to them.
</Warning>

## Layout

```
viewer/
  app/            page.tsx — the console, and every view it shows
  components/     Film, Dataflow, Scrubber, MachinePanel, Ledger,
                  Spans (+ spans/Waterfall, Swimlanes, Rollup), Topology
  lib/            trace, frame, layout, spans, design, glyphs, theme,
                  playback, record, ledger, runs
  checks/         the checks, and the Python they are checked against
  out/            the committed static export
build/served/     what the sweep writes and the picker reads — the last sweep, and nothing else
build/results/       where a project's runs land, and what the lab server serves
build/traces/     this repo's own scratch directory, for the sweep below

```

The CLI uses one verb for each viewer operation: `build`, `serve`, `dev`, `check`, and
`traces`. This keeps export and serving paths consistent.

## `losim dev viewer check`

Everything about the viewer that **a node can decide** is checked in one command. It
needs `losim dev viewer traces` because checks use generated runs rather than fixed
fixtures.

| | |
|---|---|
| `glyphs` | do the glyph paths match the Python, **character for character** |
| `parity` | does the layout port compute the same layout, on every trace |
| `ledger` | does the accruing ledger close on `losim bill`, to the rappen |
| `cost` | is a frame cheap enough to be a frame, at the largest system |
| `console` | do the console's views render, and does any ruler move under the clock |
| `author` | does what the designer writes load, and is what it must refuse refused |

<Note>
The checks import the Python modules listed here. The remaining files under `view/`
belong to the abandoned renderer:

```
view/losim_view/design.py     216 lines   imported by viewer/checks/glyph_ref.py
view/losim_view/glyphs.py     155         imported by viewer/checks/glyph_ref.py
view/losim_view/layout.py     383         imported by viewer/checks/layout_ref.py
view/losim_view/trace.py      335         imported by viewer/checks/layout_ref.py
```

The reference scripts put `view/` on `sys.path` and import these modules directly, so
deleting any of the four breaks `losim dev viewer check`.

`view/losim_view/film.py`, `view/dataflow.py`, and `view/sheet.py` are the manim
sidecar. The last two have no importers, and `film.py` is imported only by them.
This environment has no `manim` installation, so these files have no effect on the
viewer checks.

The glyph paths use SVG's convention and are compared by **string equality** rather
than by visual inspection.
</Note>

Use `losim dev viewer serve` to check MP4 playback, larger systems, and serving
without npm.

## Implementation decisions

<AccordionGroup>
  <Accordion title="Every pixel is a pure function of (trace, t, selection)" icon="function" defaultOpen>
    Each pixel depends only on the trace, time, and selection. Views hold no state
    between frames, so scrubbing and recording use the same code path:

    - the transience rule excludes finished calls from the frame. The renderer does
      not remove or retain them;
    - scrubbing and playback use the same operation;
    - recording uses the same code path as playback, with a different clock driver;
    - the views cannot disagree, because they are functions of one value.

    If you find yourself adding state to a view, that is the thing to push back on.
  </Accordion>

  <Accordion title="Attribution preserves the price" icon="scale-balanced">
    Pointing at a node shows its cost. The viewer must also identify which line owns
    that cost. The amount stays fixed while the attribution changes.

    Attribution can belong to one node, a node's share of a system total, or
    **nobody**. Late penalties belong to the job, so spreading them over nine nodes
    would invent an unsupported attribution.

    The classification is matched against the exact line labels `losim.price.Bill`
    writes. The coupling is deliberate and checked: an unrecognised line is `unknown`
    and attributed to nobody, rather than guessed at.
  </Accordion>

  <Accordion title="Colours are passed as values" icon="palette">
    The recorder serialises the `<svg>` into a standalone image. That image has no
    page from which to inherit `var(--ink)`, so a film themed through CSS records as
    black on black.

    The theme comes down as a **prop**. `lib/theme.ts` carries the ground (surface,
    strokes, greys) and follows `prefers-color-scheme`; `lib/design.ts` carries the
    meanings (amber near a cap, red past it, a task's hue) and does **not** change
    between themes.
  </Accordion>

  <Accordion title="React subscribes to the clock" icon="stopwatch">
    At 60 fps a clock in `useState` is sixty re-renders of the whole tree per second,
    and the scrubber, the panel and the views do not all need that.

    So `t` lives in a plain object a `d3.timer` advances, and components subscribe
    through `useSyncExternalStore`, each deciding how much of it it needs. The
    snapshot has to stay a primitive, or every subscriber re-renders forever.
  </Accordion>

  <Accordion title="Runtime dependencies" icon="box">
    `d3` and `mediabunny`, on top of Next and React. elkjs, Radix, framer-motion and
    react-virtual were each considered and rejected.

    Extra dependencies increase the chance that the viewer will stop building when
    the course runs again.
  </Accordion>
</AccordionGroup>

## `next.config.mjs` settings

| | |
|---|---|
| `output: 'export'` | a static site served by `losim serve` or another static server |
| `trailingSlash: true` | `/index.html` paths, which static servers can serve without Next-specific routing |
| `turbopack.root` | a pinned project root, so an unrelated `package.json` higher in the tree cannot change it |

## Trace durations in `lib/trace.ts`

| | |
|---|---|
| `trace.duration` | covers **every event**, including work after the job |
| `trace.jobRefMs` | `meta.durationRefMs`, the duration used for billing |

They differ because the heap walk runs every eighth tick, so an out-of-memory event
can occur *after* the job it ended. Clipping the trace at the job's end would remove
that event from the scrubber and the bill.

<Warning>
Use `jobRefMs` for anything that must agree with `losim bill`, and `duration` for
anything that must be able to *show* the whole run.
</Warning>

## `losim dev viewer traces`

Writes what a static page cannot discover for itself:

```bash
bin/losim dev viewer traces                 # build/traces — your runs, and nothing else
bin/losim dev viewer traces build/mine      # one directory, or one file, anywhere on disk
bin/losim dev viewer traces --suite         # ...and the reference suite's
```

**Only `build/traces` is used by default.** Other collections must be requested, so
students see their own work. For each trace, the command copies the file, writes
`<name>.bill.json` beside it when the bill is missing or stale, and rewrites
`index.json` with the same code that answers `/traces/index.json` when losim is the
server. A listed directory that exists but yields no traces reports that result.

Each run is tagged with its source, and the picker groups runs by that tag with
yours first. `dev viewer serve` forwards its arguments here, so
`bin/losim dev viewer serve ~/my-project/runs` serves traces from another project.
losim is a library, and project traces can live outside this repository.

<Warning>
`build/served` is a **mirror of the last sweep**. Each sweep removes files that were
not included, so the collection reflects the current request.
</Warning>


<Note>
If the bill is missing, the film still plays and cost is absent. The viewer does not
invent prices.
</Note>

## Design data

`lib/design.ts` holds colours, sizes, proportions, and their selection rules as data.
The module is independent of d3 and React. Keeping this data outside components
prevents each component from reimplementing it.

The drawing uses these layers:

| layer | how it is drawn | what it says |
|---|---|---|
| system | thin dark strokes on paper, data in pale green | what exists |
| mechanics | small italic serif, parenthesised | what an edge does |
| narration | bold red, numbered | what you are being shown |

<Warning>
**Red marks annotations rather than system state.** It is the lecturer's pen. Filling
system shapes with red would remove that distinction.
</Warning>

`lib/glyphs.ts` holds the geometry as SVG path data, authored origin-centred with **y
down**, SVG's browser convention. The path strings are checked against the Python
renderer by **string equality**.
