## Short version

Run a simulation and its trace appears in the results directory:

```java RunExperiments.java
Experiments.here()
        .run("main.yaml")
        .show();
```

<Note>
**`build/results` is the source of the picker.** The lab server lists it on every
request. Delete a trace and it disappears; add one and it appears.

The directory is created even when it is empty.
</Note>

**`show()` opens the viewer on the runs it made.** The lab server on port 8000 shows
all traces in the directory. Both use the same files; they differ only in the initial
selection.

<Warning>
The manual works with an empty picker. If `build/results` is empty, run a simulation
first.
</Warning>

## Or drop it on the page

Drag any `.json` onto the window. It opens as a **raw dissaly trace**, exactly as
`dissaly simulate` wrote it. Traces from other runs and incomplete runs work too.

## Server contents

The server provides the static viewer and lists runs under `build/results`. It also
lists runnable systems. It is written in Java and served by the JDK; Node and Python
are not required.

Port 8000 is forwarded automatically in both containers; in a Codespace, use the
forwarded URL from the **Ports** panel rather than `localhost`.

<Note>
The picker reads the directory on every request, so no index needs maintenance.
</Note>

## Bills beside traces

A bill is written beside each trace as `<name>.bill.json` from `dissaly bill --json`.
The viewer loads it **by convention** and uses it for the [Ledger](/viewer/views#the-ledger).


<Warning>
A trace you **drag onto the page** may have no bill, so no cost is shown. The viewer
never prices a trace itself.

A run made by pressing ▶ has its bill beside it because pricing is part of the run.
</Warning>


## Linking to a moment

```
http://localhost:8000/?run=mine&t=2400&view=spans&sv=waterfall&fail=1
```

The URL carries the run, instant, view, sub-view, pinned node, ledger state, and
filters. A URL can therefore identify a specific failure view.

A second run goes in the same URL as `vs=`, so a **comparison** is a link too:

```
http://localhost:8000/?run=mine&vs=mine-fixed&t=2400
```

## Trace files

| | |
|---|---|
| `build/results/<name>.json` | the trace — the only artefact that matters |
| `build/results/<name>.bill.json` | what it cost, for the Ledger |

Both files live under `build/results` and are gitignored. Nothing else is copied.


## Incomplete traces

Open incomplete traces as well. The trace is written either way, and
`meta.completed: false` appears as a red **did not finish** chip.


Spans still open at the end are closed as `ABANDONED`, so the viewer can render them.
