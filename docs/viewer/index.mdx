A trace is a collection of JSON objects. The viewer opens **a raw `losim simulate`
trace** directly, without a preprocessing step.

## Try it

In a Codespace or devcontainer, the lab server starts at **http://localhost:8000/**.
The picker lists runs under `build/results` that exist on disk.

To choose runs explicitly, `show()` opens the viewer on the runs it created:

```java RunExperiments.java
Experiments.here()
        .run("main.yaml")
        .show();
```

<Note>
**Every example in this manual makes its own trace.** The pages do not depend on a
shared set of prepared runs.
</Note>

<Note>
The page is a committed static export served by the JDK. It works in the devcontainer,
on a laptop, and in a Codespace.

`npm` belongs to whoever *changes* the viewer. [Developing it ->](/viewer/developing)
</Note>

## The clock is in reference milliseconds

<Note>
The scrubber reads the clock **used by the simulation**, not the host's compressed
clock. It therefore matches the durations written in YAML.
</Note>

<Warning>
**Playback speed varies, and `1x` does not mean one simulated second per real second.**
Short messages would otherwise be difficult to inspect.

The clock therefore **slows down for quick events**, keeping each message leg and
work interval visible for at least a second. The **hold** button cycles
`1s -> 0.5s -> 0.25s -> off`.
</Warning>

Only playback pace changes:

| | |
|---|---|
| **monotone** | trace time never goes backwards, so nothing is reordered and nothing overlaps that did not overlap |
| **read at the true instant** | every number on screen is taken from the trace at the trace time the playhead is at — a node's memory at 400 refMs is what it was at 400 refMs |
| **the scrubber is still refMs** | the axis is unchanged; only the speed along it varies |

**The film is longer than the run, often much longer.** The viewer displays the film's
total duration beside the elapsed time.

Turn `hold` down or off to approach the run's original playback speed.

### The `fit` rate

`fit` plays **the whole film in thirty seconds**. It preserves the pacing proportions
while reducing the total playback time.

The one-second floor applies at **`1x`**. At `fit`, each moment gets
`30s / the film's length`:

| | run | film | each moment at `fit` |
|---|---|---|---|
| a small run | 5.2s | 57.0s | ~0.53s |
| a run full of failures | 8.9s | 165.0s | ~0.18s |

Use `fit` for an overview and `1x` for detailed reading. `hold` controls the film's
timing shape; `fit` controls total viewing time. Pressing a numbered rate clears
`fit`.

<Tip>
Turn `hold` **off** and `fit` plays the whole run in thirty seconds at a constant
rate.
</Tip>



<Tip>
**Do not judge relative duration from the film.** Playback pacing changes the visual
timing. The [waterfall](/viewer/views#spans) uses a linear axis for duration.
</Tip>


## Status

The console has a rail of pages. **Runs** is the gallery. **Simulations** lists,
creates, edits, and runs simulations. **Overview**, **Film**, **Usage**, and **Cost**
read one trace and share its clock. **Spans** and **Topology** are sub-views inside
Film. [What each one shows ->](/viewer/views)

Two runs can be watched **side by side on one clock**. Pick a second from
`compare with…`; the viewer shows their relative cost below the films.
[How that works ->](/viewer/views#two-runs-on-one-clock)


## Film and video export

An earlier Python prototype rendered a run as a **video file**. It was replaced
because a video cannot be hovered, scrubbed, or queried.

The current viewer keeps playback and adds interactive views. Each element is a pure
function of its frame, so **scrubbing, playing, and recording share one code path**.

The Python modules remain the **reference implementation** for the port, checked glyph by
glyph and layout by layout. The video renderer is not one of them.
[How that is checked ->](/viewer/developing)

<Note>
The recorder's MP4 follows the film. Because the clock is an encoder input, a slow
laptop produces the same timing as a fast one, but takes longer.
</Note>

## Stack

| | |
|---|---|
| **Next 16** + **React 19** | `output: 'export'` — a static site, no server |
| **d3 7** | scales, timers, geometry |
| **mediabunny** | MP4 export through WebCodecs |

The viewer does not use elkjs, Radix, framer-motion, or react-virtual. It fetches
nothing at runtime, so it does not depend on network availability.
