## The model

<Columns cols={2}>
  <Card title="Your system" icon="code">
    Ordinary Java, ordinary `.proto` files, ordinary generated stubs. Real
    transport, real marshalling, real allocation, real threads.
  </Card>
  <Card title="losim" icon="layer-group">
    gRPC interceptors that slow calls or drop them, a node model that caps
    memory and disk, and a scale engine that shrinks the world and projects the
    result back.
  </Card>
</Columns>

An assignment has two parts: **YAML** for the system and **protobuf plus Java** for
the implementation. Your program calls peers over `io.grpc.Channel` and receives
the messages declared by your schema. The simulation defines call costs, nodes,
and failures.

The service losim asks you to implement is `losim.Job`. It uses losim's schema and
has one node that runs it.

The measurements describe the program under test. An out-of-memory report means
that the simulated node reached its memory limit.

<Note>
The toolchain is vendored into the repository. The same commands work on a laptop,
in the devcontainer, and in a Codespace without downloading or generating build
dependencies.
</Note>

## Workflow

<Steps>
  <Step title="Write a schema">
    A `.proto` with your services and messages. Nodes communicate through gRPC.
  </Step>
  <Step title="Write services, one of them losim's">
    Handlers are plain methods that can be called from a unit test. The entry service
    implements `losim.Job`, which losim defines in its own schema.
  </Step>
  <Step title="Write a simulation">
    A YAML file describing the nodes, their Java files, zones, and failures.
  </Step>
  <Step title="Simulate it and look">
    One command produces one trace. The bill, viewer, and assertions read the trace.
  </Step>
</Steps>

## Measurements

<AccordionGroup>
  <Accordion title="Small nodes enforce memory limits" icon="memory">
    A node's memory cap is enforced against a retained-heap walk, which measures
    what the node is still holding, not what it allocated. Those are different
    numbers. Retained memory determines whether the node runs out of memory.

    [Node model ->](/engine/node-model)
  </Accordion>
  <Accordion title="Node concurrency determines queueing" icon="microchip">
    Each node gets one thread pool sized to its vCPU count. Four concurrent calls
    into a two-vCPU node queue, and the wait shows up in the trace as its own
    event.

    [Concurrency inside a node ->](/write/concurrency)
  </Accordion>
  <Accordion title="Unsupported projections are omitted" icon="chart-line">
    Above `scale: 1` the engine fits a law per resource and then checks whether it
    bends. When the result is unsupported, the field is empty and includes a reason.

    [Engine refusals ->](/simulate/refusals)
  </Accordion>
  <Accordion title="Measurements outside the model are marked" icon="triangle-exclamation">
    Reading the real clock, writing a real file, opening your own channel, and
    sharing a static field between nodes do not throw. The run records a trust marker
    because those values do not describe the simulated node.

    [Trust markers ->](/engine/trust)
  </Accordion>
</AccordionGroup>
