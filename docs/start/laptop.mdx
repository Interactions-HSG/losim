## Requirements

| | |
|---|---|
| **A JDK, 21 or newer** | dissaly compiles at `--release 21`. The container ships 25. |
| **git** | for the vendored jars, which are committed. |

Gradle is not in that list. `./gradlew` is committed, and `bin/dissaly` runs it, so the
build is the same 9.2.0 on a laptop as it is in CI rather than whatever a package
manager last installed. It fetches that one Gradle on first use and checks its
sha256; nothing else is fetched to build or to run.

## Build and check

```bash
bin/dissaly dev test    # dissaly's own acceptance criteria, plus one plain JUnit test
bin/dissaly dev suite   # the reference suite
```

Both commands build `build/dissaly.jar` first. `bin/dissaly` runs `./gradlew jar` and then
starts the JVM.

## Supported platforms for `protoc`

`./gradlew jar` does not need `protoc`; it only compiles the simulator. Commands that
compile a `.proto` (`dev test`, `dev suite`, or your own build) select a vendored
binary from `vendor/bin/`:

| host | binary |
|---|---|
| macOS, Apple silicon | `protoc-osx-aarch_64` |
| Linux, x86-64 | `protoc-linux-x86_64` |

<Warning>
On other platforms, such as Linux ARM, Windows, or an Intel Mac, the command reports
`no vendored protoc for <uname>`. Use the devcontainer. Adding a platform requires a
committed binary; builds do not fetch tools at runtime.
</Warning>

## Heap

The bundled scripts give runs `-Xmx3g`. Before choosing a run size, the scale engine
checks the host heap and refuses a size that does not fit:

```
at 8000 units the system would hold 4200 MB, and this host offers 1843 MB to
work in — the run does not fit the laptop it is meant to fit on
```

If this occurs, increase the JVM heap or use a host with more memory.

## Editor setup

The repository ships `.vscode/settings.json` pointing the Java extension at
`vendor/jars/*.jar`, so imports resolve before a build. Any editor works; the
simulator compile classpath uses those committed jars.
