You have a working gRPC Java system: a `.proto`, handlers, a server, and a client.
losim runs **those handlers** unchanged on simulated nodes and network links, then
reports the design's cost.

```bash
curl -sSLo losim.jar https://github.com/Interactions-HSG/losim/releases/latest/download/losim.jar
java -jar losim.jar adopt .
```

<Note>
Commit first. The command moves files with `git mv` and refuses a dirty tree unless
you pass `--dirty`.
</Note>

## Adopt command

| action | excluded |
|---|---|
| `git mv src/main/proto -> proto/`, `src/main/java -> src/` | rename a package or rewrite an import |
| write `build.gradle.kts`, `./dissaly`, `AGENTS.md`, a first simulation, `.gitignore` | overwrite a file it did not author |
| move `build.gradle` aside to `build.gradle.bak` | delete a `.java` |
| print every Java edit still needed, with a line number | make one |

**The command does not write Java.** Extracting a nested handler can change
initialization, and turning a client into `losim.Job` requires deciding which lines
are design logic and which are transport setup.

It records the required work and its findings in `AGENTS.md`.

## Required edits

### The handler moves out of the bootstrap

```java
public class HelloWorldServer {                     // all of this goes
  public static void main(String[] args) { … }
  static class GreeterImpl extends GreeterGrpc.GreeterImplBase {   // this stays
    @Override public void sayHello(HelloRequest req, StreamObserver<HelloReply> out) { … }
  }
}
```

becomes a file of its own, and the rest is deleted:

```java
public final class GreeterImpl extends GreeterGrpc.GreeterImplBase {
    @Override public void sayHello(HelloRequest req, StreamObserver<HelloReply> out) { … }
}
```

<Warning>
**The handler must be top-level.** The trust verifier walks a nested class
together with the class enclosing it. The bootstrap's own server, channel, and
statics are therefore read as part of the service, and every figure that node
reports is marked. [Trust rules ->](/ref/trust-rules)
</Warning>

Make the handler top-level, give it a no-argument constructor, and put it in a file
named after the class. `runs:` names the file, and losim creates a fresh instance on
node restart.

### The client becomes `losim.Job`

The client drives calls, which is the role of `losim.Job`.

<CodeGroup>
```java before
ManagedChannel channel = Grpc.newChannelBuilder("localhost:50051",
        InsecureChannelCredentials.create()).build();
try {
    var stub = GreeterGrpc.newBlockingStub(channel);
    var reply = stub.sayHello(HelloRequest.newBuilder().setName("world").build());
    logger.info("Greeting: " + reply.getMessage());
} finally {
    channel.shutdownNow().awaitTermination(5, TimeUnit.SECONDS);
}
```

```java after
public final class Greeting extends JobGrpc.JobImplBase {

    @Override public void load(Input in, StreamObserver<Workload> out) {
        out.onNext(Workload.newBuilder().setCount(in.getCount()).build());
        out.onCompleted();
    }

    @Override public void run(Workload work, StreamObserver<Result> out) {
        var here = Losim.current();
        String peer = here.peersServing("Greeter").get(0);
        var stub = GreeterGrpc.newBlockingStub(here.channelTo(peer));
        var reply = stub.sayHello(HelloRequest.newBuilder().setName("world").build());
        out.onNext(Result.newBuilder().putAnswer("greeting", reply.getMessage()).build());
        out.onCompleted();
    }
}
```
</CodeGroup>

Remove the channel builder, host and port, and `shutdownNow`. **Find peers by the
service they serve, not by an address.**
[Calling peers ->](/write/calling-peers)

`Load` has no data to build here, so it returns the count it received. A real
workload should read its input there, outside the simulated clock.
[losim.Job ->](/ref/losim-proto)

## Declare call costs

`adopt` writes a simulation with every RPC at `fixed: 0 refMs`. Replace those values
before measuring. A zero duration produces no queueing, contention, or critical path.

```yaml
simulatedDuration:
  src/main/java/io/grpc/examples/helloworld/GreeterImpl.java:
    SayHello: { fixed: 3 refMs }
```

losim cannot measure this reliably at probe size: the workload is reduced while the
host CPU still runs at full speed.
[Duration declarations ->](/write/duration-declarations)

## Resulting project layout

```
proto/            your schema, moved
src/              your Java, moved and otherwise untouched
gen/              what protoc writes, beside the schema. Generated; gitignored
simulations/        1-one-call.yaml, and every one you write after it
build.gradle.kts  losim, protoc, and the toolchain task
losim             the launcher: `./dissaly build`, `./dissaly simulate`, `./dissaly serve`
AGENTS.md         findings from the classes below
build.gradle.bak  what your build used to be
```

```bash
./dissaly check     what is still between this and a run
./dissaly build     generate from the schema and compile
./dissaly simulate simulations/1-one-call.yaml
./dissaly serve     the lab, on :8000
```

## Finding categories

`adopt` and `check` print the same finding categories because they describe
different classes of result.

<AccordionGroup>
  <Accordion title="Refused: the run stops" icon="ban">
    The loader reports these with a line number before anything starts: for example,
    a streaming RPC, a non-`ImplBase` service, or a duration for an unserved method.
  </Accordion>
  <Accordion title="Untrustworthy: the run contains an invalid number" icon="triangle-exclamation" defaultOpen>
    The verifier reports these per node in the trace. Examples include a custom
    channel, custom thread, real sleep, wall clock, or real file access. The run can
    complete while the marked number is invalid. [The rules ->](/ref/trust-rules)
  </Accordion>
  <Accordion title="Dead code: it has no measured effect" icon="ghost">
    A `main` method, shutdown hook, `awaitTermination`, credentials, a fixed thread
    pool, a logger, `grpc-netty-shaded`, or the `application` plugin.

    These do not affect a measured value, so the verifier stays silent. Check `main`
    carefully: without an explicit simulation, losim can select the first class with
    one and attempt to bind a port.
  </Accordion>
</AccordionGroup>

## Rejected project inputs

It refuses a `pom.xml`, a multi-module `settings.gradle`, a directory without a
schema and service, or a dirty tree without `--dirty`.
